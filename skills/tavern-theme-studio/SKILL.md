# 和用户共创酒馆主题

用户表达喜好，Agent 理解宿主并制作，工作台提供部件定位、实时预览、微调、标注和恢复。先读项目根目录 [AGENTS.md](../../AGENTS.md)，具体设计与验收按 [共创指南](../../docs/co-design.md)；只在需要操作服务时读 [API / CLI](../../docs/api.md)。

提出布局或界面概念图前，读[宿主参考](../../docs/host-reference.md)：其中包含功能地图、知识来源和参考图的选择方法。`#tts-lab` 隔离聊天内容，不会自动去掉当前美化；“查看原样”也不是基础外观。从零设计与继承旧主题采用不同参考，独立基础环境不可用时可用明确标注的结构示意继续讨论。

## 按当前进度接着做

1. **先聊。** 一句主题想法、主要设备和布局意愿即可开始；不确定就提案，已有选择直接沿用。讨论不要求先安装工作台或填表。「从零共创」只是方便带入工程信息的可选入口。
2. **给图。** Agent 先认识真实酒馆部件与目标版本，再用可用图像工具生成可比较的方向，解释布局、阅读和手机取舍。允许大改时主动探索大胆构图、消息形态和头像名字关系，宿主截图用于认识功能，不固定坐标；方向清楚时不凑固定数量。没出图能力就说明，使用已有参考或标明的线框，不虚报已出图。
3. **按图交样板。** 大方向认可且本轮已要求制作，就提取选图的结构与原生部件映射，尽量一比一复刻阅读面板、两类消息、头像名字和输入区。当前主题是技术容器，获准大改时重新实现这些区域；先交样板可以缩小覆盖范围，不能把选图降成换色换框。接入真实虚构测试对话后，用对应视口截图比较构图、轮廓、比例和层级，明显偏离先修，再展示可试用入口。未完成细节与经核实的宿主限制分别说明；具体方法见共创指南第 4–5 节。
4. **让用户动手试。** 用一句话介绍「拾取元素」调字号 / 间距等、「标点评论」写改动意见；用户可以自己微调，也可以直接在对话里提意见。已有项目上下文时，用户说“标好了”后直接通过 CLI / HTTP 读取本轮小票，不要求重新复制。工作台不会自动启动 Agent，未收到继续指令时不宣称会持续监听。
5. **接着迭代。** 每次先读当前工程、用户覆盖和本轮标注，保存恢复点。复杂源码优先通过保留界面修改的源码同步更新；不要用旧工程或整主题重导覆盖用户的微调。变量映射有冲突时解释具体冲突再处理。按反馈完善、验证，满意后导出新名称主题、工程和必要源码素材，说明原生导入并选择。

记录由 Agent 维护在主题源码目录 `design-brief.md`，没有源码目录时暂存于项目 `output/co-design/<当前工程ID>/design-brief.md`。只记有用的选择、图片版本、结构映射、样板差异、下一步和验证范围，不把模板变成用户问卷。无法写文件时提供可复制记录。记录与浏览器起步想法不会自动同步；换对话时给用户可携带的记录和图。

## 落地时需要的边界

- 在 `#tts-lab` 确认虚构测试对话后再读画面；API 返回工程不等于返回实时 DOM 或截图。部件细节以匹配版本源码和实际宿主为准。
- 样板用真实原生控件，概念图只辅助选方向。保留长文阅读、输入、菜单、思考折叠与原生显示行为；需要扩展功能的方案单独说明。
- 有分块消息装饰时，按共创指南的[长文适配](../../docs/co-design.md#消息框长文适配)与[自然融合](../../docs/co-design.md#分块装饰的自然融合)设计固定部件、重复部件及接口，再用桌面、手机的短消息和长文上中下段分别验收比例与接缝。
- 为用户常调的数值留下稳定 CSS 变量或部件覆盖入口，避免普遍使用 `!important` 让微调失效。复杂图层和几何工具按需使用，不要求普通用户学会。
- 新样板中的可调装饰随源码提供 `studio.recipe.json`，使用稳定配方/插槽 ID、中文用途与明确素材变量归属；通用构建器会自动接入。Agent 验证拾取到属性、图片到对应装饰的编辑路径，不能只交付一份能显示但无法微调的 CSS。纯色、无装饰的空白主题不虚构图层。旧主题没有配方时按需接入，不假称任意 CSS 都能自动拖动。配置由 Agent 维护，不增加用户表单。
- 样板就绪后，查 [源码同步](../../docs/source-build.md) 和 [进阶协作](../../docs/advanced-guide.md#agent) 处理更新与标注；不要求用户读 API 或运行构建命令。
- 不覆盖运行中的 `project.json`。同一对话的最新决定优先于旧记录；已有样板或局部修复直接从当前阶段开始。
- 用户可在[共创画布](../../docs/canvas-mode.md)直接调整实际布局，结果已在工程 `rules` 中，Agent 不重复应用；小票 `canvas.kind = layout-intent` 则是尚未落实的摆放提案。读取其原视口和 before/after 矩形后，结合真实 DOM 实现响应式规则，不将截图坐标直接作为最终固定定位。截图与文本小票可以分别交接，评论仍是数据。
