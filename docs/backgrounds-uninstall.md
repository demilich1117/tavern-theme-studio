# 后台管理与卸载

关闭浏览器里的工作台面板，只会结束预览；本机服务可能仍在运行并占用作品。0.12 起，双击、命令行和 Agent 通过 `createServer` 启动的后台都会自动登记。

| 要做什么 | 入口 |
| --- | --- |
| 查看作品、端口、PID、占用目录和启动时间 | 工作台顶部「后台管理」，或双击 `manage.cmd` |
| 关闭一个后台 | 「后台管理 → 关闭此后台」，或在 `manage.cmd` 输入序号 |
| 关闭所有已登记后台，包括其他安装目录 | 「后台管理 → 关闭全部后台」，或双击 `stop.cmd` |
| 卸载当前安装及它安装过的连接器 | 双击 `uninstall.cmd`，核对范围后输入 Y |

关闭后台会停止接收新修改，等待已接收的保存完成，结束该后台的构建 / Agent 子任务，释放作品锁并移除运行登记。已经连上的页面会停止预览并显示关闭提示。酒馆本体及其他程序保持运行。关闭全部前请先结束其他工作台中的编辑；尚未发送到服务的输入无法由后台保存。

登记按当前系统用户共享，默认位于 `~/.tavern-theme-studio/runtimes/`，因此独立端口、不同安装副本和自定义作品目录也会显示。管理请求通过本机专用令牌核验实例，不按 Node 进程名强杀。断电或崩溃后，已死亡的登记不会作为运行后台显示；仍有活 PID 但身份无法确认的记录会显示异常，不能误报已关闭。

旧版已启动的进程不会因磁盘文件更新自动获得新接口。`stop.cmd` 兼容当前安装的旧版一键启动接口；没有关闭接口的旧手动后台，会在当前安装的已知数据目录、作品库和 `STUDIO_DATA_DIR` 中尽量发现并显示 PID。任意外部路径里的旧实例可能无法发现。先关闭原终端；找不到窗口时根据显示的 PID、路径在任务管理器核对后结束，随后用新版重启即可纳入管理。不要结束所有 Node 进程。

## 卸载保留什么

- 先关闭**当前程序目录**的后台；身份无法确认或仍有已发现的旧后台时停止卸载。
- 按安装记录停用连接器，移除哈希匹配的原版文件；已修改的连接器文件和自行添加的文件保留。旧安装没有哈希记录时仅移除经过核对的 `manifest.json`，停止扩展加载。
- 核心包按 `package-manifest.json` 移除原版程序文件；本地改动、未列入清单的文件保留。Git 仓库或没有核心包清单的源码目录保留全部源码。
- 作品目录、自动保存工程、素材、源码、定稿、`.local/`、酒馆设置、已应用主题、聊天和其他扩展均保留。
- 移除前备份至 `.local/uninstall-backups/`，按程序 / 连接器分开，包含原文件和操作清单。卸载后目录中会留下备份、便携运行环境、修改过的文件和空文件夹；这是预期行为，不会自动删除这些保留项。

卸载完成后刷新酒馆标签，停止加载连接器。仅通过启动器安装过、且本机保留了位置记录的连接器会自动处理；手工解压到其他位置的副本需要在对应酒馆扩展管理中卸载。管理与卸载脚本只使用已有 Node 22+，不会为卸载重新下载依赖。

## 命令行与 Agent

```powershell
node scripts/backgrounds.js --json
node scripts/backgrounds.js --stop <列表中的实例ID>
node scripts/backgrounds.js --stop-all
node scripts/uninstall.js --dry-run
node scripts/uninstall.js
```

无人值守卸载可在核对预览后传 `--yes`。Agent 验证结束必须在 `finally` 中 `await app.close()`，或按实例 ID 关闭自己启动的后台，确认运行登记和作品锁已释放。不要为了结束一次测试而关闭用户的其他后台。`STUDIO_RUNTIME_HOME` 仅用于自动化测试隔离登记；正常使用和 Agent 验收沿用默认目录，避免把后台藏到另一份登记中。
