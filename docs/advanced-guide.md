# 进阶使用 · 从微调到制作自己的主题

进阶使用沿用入门时的同一个工作台、连接器和工程。先完成一次 [普通用户入门](../README.md#beginner)，再按需要选择下面的工具。

[看 DOUBLECHEESE 进阶漫画](comic-guide.md#page-2) · [API / CLI 参考](api.md)

只有想法、尚未选定设计方向时，可以直接和 Agent 聊；已有工作台时也可通过「从零共创」复制一次起步信息，之后在同一对话里看图和反馈；见 [共创指南](co-design.md)。下面的工具用于把已选方向落地，以及继续维护现有主题。

## 1. 先确认你正在改哪一份主题

从酒馆里切换了主题后，工作台的当前工程不会自动变成另一份主题。选择「作品 → 新建作品 → 接入酒馆当前主题」，核对名称，再点「创建作品并开始编辑」；也可在「素材 → 主题图片」进入同一操作。

工作台先给旧作品留恢复点，再创建独立作品。旧图层、变量覆盖和部件规则不会混入，旧源码同步在离开时暂停。需要返回时从「作品」选择原作品；同一作品的阶段恢复使用定稿或「备份 → 保存 / 恢复版本」。

「读取当前主题为底层」是另一种操作：它保留已有部件规则和高级 CSS，但清除变量编辑并重新识别。只有明确要沿用这些编辑时才选择它；接入陌生主题优先使用新工程入口。

详细流程与冻结分析包见 [主题接入与分析](theme-analysis.md)。

## 2. 编辑变量、消息细节与 CSS

| 工具 | 适合处理 |
| --- | --- |
| **拾取元素 / 选择编辑对象** | 颜色、透明度、边框、圆角、四边间距、字号等常用属性 |
| **主题样式** | 基础主题 `custom_css` 中已有的 CSS 变量 |
| **对象列表与相关部件入口** | 正文、名字、时间戳、思考栏、引用、代码、表格、消息操作栏和消息伪元素 |
| **进入画布** | 「实际布局」直接调整位置 / 尺寸；「蓝图」暂存多个部件的布局意见，保存一张小票交给 Agent |
| **高级 CSS** | 控件无法表达的选择器、状态与复杂样式 |

「主题样式」可以搜索变量、仅看已修改，并查看注释、行号、选择器和条件。数字使用滑块，颜色支持透明度，复杂的 `var()`、`calc()` 和字体列表保留文本形式；文本值按 Enter 或点击「应用」。

同名变量按原始声明分别编辑，手机或局部变量不会被合并为全局变量。变量面板只处理基础主题内普通未转义变量名的声明；外部 `@import`、扩展文件和高级 CSS 中的变量要在各自源码中修改。色盘编辑会转换成 sRGB 十六进制，未编辑的原值保留。

拾取某条消息后，部件规则仍作用于同类消息。伪元素 `::before` / `::after` 通过部件列表选择；选择它不会自动创建装饰内容。

最终 CSS 的组合顺序为：

```text
基础主题（含变量编辑）
    → 部件、断点与图层规则
    → 高级 CSS
```

高级 CSS 按原文应用，可能覆盖控件设置。外部字体和背景地址由浏览器加载，普通导出会保留这些外链。

### 数值改了，画面为什么没变？

先确认当前编辑范围，再展开「技术详情」，检查部件是否匹配。通过「查看计算值与样式来源」比较设置与浏览器实际结果，查看匹配到的声明、`!important`、样式表和继承候选。

原主题、内联样式、扩展样式和更强的 `!important` 都可能影响结果。诊断列表是候选来源，不是完整层叠排名；无法读取的跨域样式表会计数。容器查询、作用域、嵌套、动画等复杂情况需要结合浏览器开发工具核对。

## 3. 整理素材与可调装饰

建议先清点，再替换或拆分：

1. 在「素材 → 主题图片」查看图片、使用位置和 CSS 装饰。需要帮助判断时点「复制分析给 AI」。
2. 在「素材 → 素材库」上传本地图片、登记图片直链，或使用已有素材。
3. 点击图片的「调整装饰」或「打开素材库替换」可带着当前选择进入对应位置；同一图片对应多个变量时再选择用途。需要新图层时按配方接入。
4. 调整位置、缩放和显隐，分别检查宽屏与窄屏，再保存一个版本。

清点不会改 CSS、自动生成图层或把一张合成图拆成多个图案。图片的实际用途需要结合使用位置与画面判断；第三方扩展样式、聊天正文图片和动态 DOM 不属于静态主题清点范围。

素材支持 PNG / JPEG / WebP / GIF，本地上传上限 **32 MiB / 张**，暂不支持 SVG。本地图片按 SHA-256 去重，工程内部引用为 `tts-asset://...`，预览时由连接器解析。

大装饰可以先生成缩略图或等比 WebP 变体，对照透明边缘后再显式替换。变体保留原图；动画图片不会被直接转成静态图片。素材归档保留文件，旧快照仍需用到的图片不能随意删除。

Source Hub 是可选素材目录，提供固定版本、哈希锁与离线缓存。首次上手不需要配置；已有外链也不必为了普通导出而接入 Hub。登记外链只保存地址，不等于已经下载或缓存。

进一步阅读：[装饰配方](decorations.md) · [定位、容器与断点](layouts-and-geometry.md) · [素材源、变体与依赖审计](resources-and-runner.md)

## 4. 把具体修改交给 Agent

整体构思从「从零共创」复制一次给 Agent，后续在同一对话里看图和反馈。Agent 负责记录选中图、版本与取舍，并衔接制作；用户不必重复填写。需要准确指出某个位置时可以用小票，一般意见直接在对话里说即可。起步想法存于当前浏览器，可按需下载；Agent 的设计记录另随主题交付，两者不会自动同步，也不包含在 `.studio.json` 中。

已有样板后，你能调的直接在面板调，需要 Agent 改的位置再标注。同一项目对话中的流程是：

```text
标点写需求 → 对 Agent 说「标好了，帮我处理」
    → Agent 领取、修改、验证 → 你检查效果并验收
```

1. 点击「标点评论」，再点酒馆里的目标位置。写清希望的效果，例如「手机正文再宽一点，保留头像位置」，保存小票。
2. 告诉当前 Agent 已标好，它可直接读取本轮小票。首次或换 Agent 时，在「修改意见」中复制单票 / 所选小票，粘贴到已打开本项目且能访问本机服务的 Agent 对话。
3. Agent 读取最新工程、用户微调、小票与冻结快照，核对基线后领取和处理；源码更新保留现有界面覆盖，不用旧工程冲掉你刚调好的内容。
4. 回到工作台查看待验收结果、变更与证据。在真实测试对话检查效果，再点击「验收通过」；需要继续改时重新待办。

想一次讨论多个部件的位置，可用「进入画布 → 蓝图」：确认预览尺寸和编辑范围，连续调整头像、名字等部件，再点「保存整张蓝图」。保存后自动选中新票；Agent 逐项读取范围、同类规则和工程快照后落实。实际布局已保存到工程，不重复应用；蓝图小票尚未写入主题 CSS，待落实、验证和验收后再导出。刷新前先保存蓝图。详细步骤见 [画布指南](canvas-mode.md)。

**复制小票不会自动启动 AI。** 工作台没有内置模型聊天面板。需要自动启动本机模型 CLI 时，另行配置可选执行适配器，见 [通用本机 CLI](resources-and-runner.md)。

小票会保留定位信息、视口和工程快照，不自动采集聊天正文、角色资料、HTML 或截图。截图证据由处理者另行提供；命令成功和回写完成也不等于视觉验收通过。

状态为 `open → working → review → done`。提交后工程又变化时，必须核对当前效果再验收。接口和结构化回写格式见 [小票说明](annotations-assets.md)、[API 参考](api.md)。

## 5. 用源码同步维护复杂主题

适合有可维护 CSS、主题字段和素材清单的作品。完整源码仓库可使用随附的月弧浮页配方；核心安装包不含该大型示例素材。

「从空白开始」已自动准备源码与同步。已有源码在「更多工具 → 源码同步」绑定构建配方，再开启保存源码自动同步。之后保存源码，工作台会构建候选、合并当前界面调整并更新临时预览。构建失败保留上次成功效果，冻结发行物保持独立。

候选位于当前数据目录的 `builds/<projectId>/`。恢复快照或撤销基础 CSS 会暂停自动应用，核对后通过「立即构建」或重新开启自动同步继续。

手动兼容入口：

```powershell
npm run build:folio -- --no-preview
```

这条命令需要完整源码和示例素材，只构建主题及工程。预览更新仍需通过工作台导入 / 同步；持久化应用仍走酒馆原生导入。

本机路径和程序配置不进入可分享工程。不要在服务运行时手工覆盖 `project.json`。构建配方、候选输出协议和恢复方法见 [源码同步](source-build.md)。

## 6. 验证多尺寸效果，再选择交付方式

先检查这次改动影响到的样本：长文、代码和表格、思考折叠、图片、原生编辑及预置候选回复。

「场景检查」可检查横向溢出、部件越界和可能裁切，并导出 JSON 报告。连接真实酒馆时检查的是当前画面；在「原生测试场景」定位内容后，操作酒馆原生控件。未出现的部件标为跳过。

「所有尺寸」是基础规则，「仅手机」默认覆盖不超过 767 px 的画面；进阶制作可以定义命名断点。真实响应式验收用设计工作台顶部的手机 / 电脑 / 自定尺寸切换，读回实际视口，再观察阅读区域；桌面可收起编辑区，窄屏切到「预览」。显示缩放不改变断点。

未连接时的 6 场景 × 2 尺寸示例组合可帮助试用；实际主题仍应在真实宿主中检查。虚构静态样本不覆盖所有扩展、真实流式、群聊或实体手机。

### 三种主题导出

| 模式 | 本地图片 | 外部依赖 | 用途 |
| --- | --- | --- | --- |
| **普通导出** | 内嵌到主题 JSON | 保留原有公网外链，列出依赖 | 日常安装和修改已有主题 |
| **严格离线** | 内嵌 | 要求每个依赖都有锁定、匹配的本地字节 | 希望离线使用的交付 |
| **固定外链** | 按锁定引用处理 | 重新验证固定公开 URL、类型和哈希 | 有稳定素材源的发行 |

普通导出也会拒绝缺失的本地图片和本机预览地址。未知字体 / 样式表、相对路径、无法核实的资源等会阻止严格导出；先处理报告中的依赖，再重新导出。

日常使用可直接点「应用 / 导出 → 应用到酒馆」，它使用普通导出的素材处理方式并完成原生导入与选择；等待成功回执后再关闭工作台。下载 JSON 则使用新名称，随后到酒馆「用户设置 → UI Theme」导入并选择。

原生主题只保存酒馆字段与 CSS，工程结构留在工程备份。外部图片和字体是否离线可用，取决于实际导出模式和依赖检查。

### CLI：批量修改同一个工程

默认入门启动使用 19323，独立模式使用 19321。为避免连错工程，下面从**默认数据目录的运行记录**读取实际地址；自定义数据目录时改为对应的 `runtime.json`：

```powershell
$studioRuntime = Get-Content -LiteralPath '.local/native-lab/runtime.json' -Raw | ConvertFrom-Json
$env:STUDIO_URL = $studioRuntime.address

node scripts/cli.js status
node scripts/cli.js targets
node scripts/cli.js snapshot-save '批量修改前'
node scripts/cli.js set assistant padding 24px
node scripts/cli.js set assistant padding 12px mobile
node scripts/cli.js undo

New-Item -ItemType Directory -Path 'output' -Force | Out-Null
node scripts/cli.js export output/my-theme.json
node scripts/cli.js backup output/my-theme.studio.json
```

页面和 CLI 共享一个当前工程，CLI 修改也会更新页面。上述例子最后撤销手机内边距修改，保留所有尺寸的修改；请按自己的目标调整数值。

HTTP 写入需要刚读取的 `sessionId`、`projectId`、`fingerprint`、`revision` 和本机 token。收到过期基线的 409 后重新读取、核对意图，不要无条件重复写入。完整命令见 [API / CLI](api.md)。

## 7. 备份、升级和恢复

| 保存内容 | 包含什么 | 不包含什么 |
| --- | --- | --- |
| **主题 JSON** | 酒馆字段、最终 CSS、按模式处理的素材 | 可视化编辑结构与历史 |
| **单文件工程备份** | 当前工程、变量编辑、图层、规则、高级 CSS、内嵌本地图片 | 其他命名快照、小票、本机执行和源码绑定配置 |
| **分文件工程备份** | 当前工程、清单和独立本地素材文件 | 其他快照、小票、外部依赖和本机源码 |
| **完整数据目录备份** | 本机工程、素材、快照、小票及配置 | 目录外的主题源码；外链资源不保证已缓存 |

大工程可用分文件备份，避免单文件 JSON 超过 48 MiB 导入上限。先按上一节配置 `STUDIO_URL`，再运行：

```powershell
New-Item -ItemType Directory -Path 'output' -Force | Out-Null
# 目标目录必须尚不存在，每次备份使用新目录。
node scripts/cli.js backup-files output/my-backup
node scripts/cli.js restore-files output/my-backup
```

恢复前会核验清单和文件，完成后暂停源码自动应用；核对效果后再恢复同步。完整历史备份应先停止工作台，再复制整个实际数据目录，同时保留主题源码。

默认数据目录为 `.local/native-lab/`，高级独立模式为 `.local/`；自定义位置可在「主题」中的存储信息或 `GET /api/session` 返回的 `dataDir` 确认。同一数据目录只能运行一个实例。

| 启动入口 | 默认端口 | 默认数据目录 |
| --- | --- | --- |
| `start.cmd` / `npm start` / `npm run lab` | 19323 | `.local/native-lab/` |
| `npm run start:standalone` | 19321 | `.local/` |

`STUDIO_PORT`、`STUDIO_DATA_DIR`、`TAVERN_URL` 分别指定工作台端口、数据目录和实际酒馆地址。首次种子 `npm run lab -- examples/starter.theme.json` 只在尚无工程时读取，不覆盖已有数据。默认和独立模式的数据各自保留，不自动搬迁。

`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 重做，最多保留当前服务会话 100 条记录；在文本框中保留浏览器文本撤销。重启保留最终工程与命名快照，不保留撤销栈。

升级前备份数据，更新程序时保留它。启动检查用 `npm run doctor`；锁冲突、异常恢复及发行检查见 [发布说明](release.md)。维护者在完整源码仓库运行 `npm test`、`npm run check` 或 `npm run release:check`，核心包不提供维护测试。

## 参考与验证范围

工程格式为 schema v3；工作台使用独立 Node.js 服务，酒馆仅安装连接器。临时预览使用独立样式层，停止预览、关闭工作台或酒馆页面后清除；连接失联超过 30 秒也会清理，刷新酒馆可恢复原样。

已核验宿主为 SillyTavern **1.19.0 / 06bde939f**。导入主题的原生字段保留；临时预览呈现聊天布局、头像样式等已支持的外观字段，不写入酒馆设置。未覆盖的原生行为仍需应用后检查。
