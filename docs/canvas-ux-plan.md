# 画布操作与图层的改进方案

建议按“选得到、看得清、改得准、能撤回”的顺序改进。优先统一部件选择、外部工具栏和视图操作，再完善装饰排版。酒馆主题编辑应保留真实页面结构、响应式范围和同类联动，不把消息误呈现成可随意增删的独立图片层。

此方案基于 0.13.0 源码及独立 SillyTavern 1.19.0 的真实测试对话。基础体验、选取导航和视图工具已随 0.14.0 交付；本文件保留方案取舍，未实现的项目仍为建议。当前截图与字幕视频见 [演示素材](showcase.md)。

## 后续取舍：以酒馆美化构筑为准

2026-10-15 根据用户最新要求重新排序。成熟软件只提供交互参考；新增功能必须解决具体的酒馆构筑问题，不能因为 PS / Figma 有就加入。尺寸覆盖说明、装饰贴边、九切片长文适配已随 0.14.0 交付；范围间属性复制、完整自动检查矩阵等仍是建议。原有方案中的工具清单保留为背景，不再默认按多选、对齐、参考线的顺序推进。

### 第一优先级：把已有底层能力变成直接可用的构筑操作

| 建议 | 具体使用场景 | 已有能力与缺口 | 首版范围与验收 |
| --- | --- | --- | --- |
| 尺寸覆盖与生效说明 | 电脑已经调好，手机只想改头像大小；改了值却看不出变化 | 已有断点、范围提示、基础继承、计算值和候选来源诊断，但分散在不同入口 | 在当前部件明确列出通用设置、当前尺寸覆盖和画面实际值；可清除当前覆盖、按所选属性复制到另一范围。存在差异时先解释尺寸未命中、正在看原样等可确定原因，其余连到诊断；不自动堆叠 `!important`，不把候选规则当成已证明的唯一原因。预览设备与写入范围仍独立 |
| 装饰贴边与长文适配 | 花饰固定在用户消息右上角；花框随长文延长而角部保持比例 | 已有容器 / 图片锚点、尺寸、九切片和比例锁；界面主要是数字，缺少直观构筑入口 | 提供九宫格锚点、离边距离、固定图案与可伸展区域的可视化设置，以及短文 / 长文上下段切换。首版面向已接入配方的单张装饰和九切片边框；任意异形框、多素材拼接不能自动保证无缝。只调整该身份和选定范围 |
| 真实宿主适配检查 | 一个气泡在短消息里好看，但长文、图片、思考栏或手机上出问题 | 已有七类虚构测试定位、当前画面溢出检查；`public/advanced.js` 的批量矩阵在真实宿主连接时禁用 | 在专用测试对话中依次检查双方短文、长文顶部 / 中段 / 底部、代码表格、图片、思考与编辑区域，并遍历选定宽度。先做顺序检查和问题定位，结束还原预览尺寸与滚动位置；不启动第二份可编辑宿主，不发送消息。自动报告几何问题，图案拉伸、接缝和遮挡仍列为人工视觉检查，不虚报已自动判定美观或功能正常 |

### 第二优先级：减少重复搭建

| 建议 | 具体使用场景 | 边界与实施条件 |
| --- | --- | --- |
| 消息结构配方 | 设置角色头像在左、用户头像在右；名字在正文上方；调整头像与气泡距离、消息最大宽度 | 这是消息内部结构的配置，不是把现有拖动包装成预设。当前布局入口没有直接覆盖完整角色 / 用户消息容器，需要先建立针对已核验宿主结构的配方。首版用于空白或明确兼容的样板；导入任意重构 CSS 时先检查兼容性并展示影响，不直接覆盖。短文、长文、思考、原生编辑和回复切换均须验证 |
| 部件样式复用 | 用户气泡沿用角色气泡的圆角和边框，但保留自己的位置、宽度和颜色 | 按属性组复制，默认排除身份、位置、尺寸和断点；允许明确勾选。一次复制后两边仍独立，一次撤销完整恢复。复制现有明确规则优先；计算效果与源码变量的跨工程复用需要额外处理，不把浏览器计算值全部写死 |
| 构筑时的局部比较 | 试了一组头像或气泡样式，想看它与修改前的差别，不想恢复整份作品 | 已有全局查看原样、撤销、快照和定稿。只补当前部件 / 一组修改的临时对照和差异说明，底层复用工程历史；不再建立第三套保存或版本系统 |

建议下一轮先做「尺寸覆盖与生效说明 + 装饰贴边」，再补长文适配入口和真实宿主检查；消息结构配方单独作为一轮较大的构筑能力。它们比通用框选、等距分布和无限画布更直接服务于当前项目。

### 暂缓及收敛

- 多选、对齐、参考线仅在确实需要同时摆放多张已接入装饰时再做；原生消息仍由内容流排版。当前同一伪元素插槽不能任意容纳多个独立装饰，先解决插槽与组合表达，再谈通用图层组。
- 「手机隐藏某个装饰」值得补，但当前 `visible` 是整层状态，尺寸覆盖主要在 `props` 中；需要设计可继承的范围显隐，不能把现有隐藏按钮直接改名成“仅手机隐藏”。
- 平移保留为放大检查的辅助操作；不继续扩展画布旋转、无限平移等工具。默认适合窗口时不应占据最显眼的位置。
- 不新增独立的颜色、素材、图层或历史管理系统；已有能力优先改入口和说明。像素编辑、任意 DOM 重排、装饰自动生成不作为本轮方向。

源码依据：`public/inspector.js`、`public/layouts.js`、`public/layers.js`、`public/decoration-tools.js`、`public/advanced.js`，以及 `shared/layouts.js`、`shared/decorations.js`、`shared/fixture.js`、`connector/diagnostics.js`。最新实现与宿主验收见下方及验证记录，未实现的计划不计为当前功能。

## 图层应该怎样加入

**需要统一的“部件与图层”面板。** 目前已有界面部件列表、属性面板中的相关内外层按钮、可调装饰的搜索 / 显隐 / 锁定 / 叠放顺序；需要把这些入口接到同一选择状态。

建议面板分两类对象：

- **界面部件**：按阅读面板、聊天区域、消息、头像、名字、正文、输入区等语义结构分组。可展开、搜索、定位、选取和显示修改标记。原生节点关系用于导航；列表排序不改变原生 DOM 或 CSS 叠放。
- **装饰图层**：沿用现有配方和图层 ID，显示其归属部件。已声明可调整的装饰可改名、显隐、锁定、定位和修改叠放顺序；锁定与历史直接复用已有实现。任意主题里的图片仍需先识别并接入配方。

例如点选一个用户头像，面板应显示“用户消息 → 用户头像”“仅手机”“当前匹配 2 个”，并提示调整只作用于这一范围内的用户头像。角色头像单独分组。不能把不同身份合为“消息头像”默认一起改，也不能把多个同身份头像列成可分别修改的独立图层，却仍然写同一条 CSS 规则。

桌面先在现有编辑侧栏放“部件 / 属性”页签，不立即增加常驻第三栏。手机在预览外放“选择部件”入口，打开可搜索的列表，选好后返回预览；精确属性沿用“编辑”页。

## 早期交互清单（基础选取与视图现已实现）

| 能力 | 当前情况 | 建议实现及用户收益 |
| --- | --- | --- |
| 部件树与搜索 | 列表、下拉框、相关部件分散 | 统一语义分组、搜索、选中高亮、已修改标记；解决找不到部件 |
| 重叠对象选取 | 默认取命中优先级最高的部件 | 提供“此处的对象”，列出头像 / 名字 / 消息 / 容器等有效候选；桌面右键、手机外部按钮均能打开 |
| 清楚的选择路径 | 属性面板有内外层入口 | 在画布外显示当前位置及父级入口；选中树条目与画面双向同步 |
| 悬停预览 | 普通拾取有，画布选择没有 | 桌面悬停细框与名称；选中和悬停使用不同样式；手机不依赖悬停 |
| 选择与浏览两种工具 | 画布点击选取，普通预览可操作酒馆 | 用明确的选择 / 浏览状态区分编辑与原生交互，避免点按钮时意外编辑或触发宿主 |
| 平移与定位 | 目前使用外部滚动条 | 加手形工具、桌面空格临时平移、100% 和适合窗口、定位选中对象；视图操作不得写入工程或撤销历史 |
| 常用操作的稳定位置 | 撤销、范围、画布工具分布在不同区域 | 固定外部工具区，显示当前对象 / 范围 / 保存状态；少用操作展开，输入与快捷键不抢焦点 |
| 快捷键提示 | 已有方向键、Shift、Alt、Esc、撤销重做 | 集中到可见帮助；新增 V / H 等仅在画布聚焦且非文本输入时生效，保留浏览器输入习惯 |

选取优先复用 `connector/picking.js` 的语义命中、`connector/bridge.js` 的当前对象与检查结果，以及 `public/inspector.js` 的相关部件。装饰继续使用 `public/layers.js` 和现有工程历史，避免两套选中状态。

## 限定场景后加入

| 能力 | 建议范围 | 实现前要解决的条件 |
| --- | --- | --- |
| 多选与框选 | 先做装饰，之后考虑蓝图里的多类部件 | 定义父子同时选中、同类去重、跨范围冲突；一次移动必须一次撤销 |
| 对齐与等距分布 | 优先同一容器内的装饰 | 明确按容器还是关键对象对齐；流式正文不能照坐标强行排齐 |
| 智能参考线和距离 | 先显示选中对象与其容器的边距 | 区分参考线与真正吸附；当前 8px 数值吸附不能称为对象对齐 |
| 约束与响应式规则 | 作为现有布局 / 断点的可视化入口 | 使用“靠哪边、宽度随谁变化”等可理解操作，映射到可维护 CSS；不复制另一套约束引擎 |
| 直接拖动对象 | 显式移动状态，先支持可调装饰 | 设置拖动阈值，处理滚动、选字、链接和原生消息控件；手机默认仍可滚动，不能整片内容都抢手势 |
| 锁定与隐藏 | 装饰已有，原生部件只考虑编辑锁 | “不允许误拖”和“主题中隐藏”须区分；隐藏原生按钮会改变真实功能，不能用一个眼睛图标混合两种含义 |
| 样式复制粘贴 | 同类或兼容部件的选定属性 | 提示复制了哪些属性、应用到哪个范围，保留相对单位，一次撤销 |
| 历史面板 | 复用现有撤销、快照和定稿 | 给操作命名，区分工程历史与临时蓝图历史；不新增重复保存系统 |
| 旋转、缩放及比例锁 | 装饰已有，应改善入口 | 普通正文继续改宽度 / 最小高度，不整体放大字体，也不强加固定高度 |

## 当前不加入

| 能力 | 原因及替代路径 |
| --- | --- |
| 套索、魔棒、橡皮擦、画笔、像素选区 | 属于图像内容编辑；在图片工具里处理后替换素材即可 |
| 任意自由变换、透视、将文本栅格化 | 会破坏真实页面阅读、交互和长文适配；仅装饰保留其已支持的变换 |
| 拖动原生层顺序、随意复制或删除消息节点 | 原生功能和结构由酒馆维护；先提供导航与主题布局配置 |
| 无限画布、多画板独立工程、画布旋转 | 当前目标是校验真实响应式视口，现有手机 / 电脑 / 自定尺寸已覆盖主要需求 |
| 自动把所有 CSS 图片变成可拖动图层 | 图片可能是背景、边框、遮罩或多个控件共用变量；先清点用途，再声明可调装饰 |

## 原实施顺序与验收（后续优先级以上文为准）

1. **基础体验**：外置工具栏、小把手、稳定点击范围和视图缩放。本轮已完成下述源码调整。
2. **选取闭环**：统一部件树、搜索、选择路径、重叠候选。验收被装饰覆盖的名字与头像都能明确选中，选择和属性面板一致，不改动工程。
3. **视图操作**：选择 / 浏览、平移、定位选中与快捷键帮助。验收缩放不改变断点，平移不移动对象，不抢输入框、聊天滚动或浏览器快捷键。
4. **排版辅助**：先装饰的多选、对齐、参考线；再评估蓝图多类部件。每一步验证手机、长文、恢复原样和撤销。
5. **统一教程和发布素材**：按最终界面更新操作文字、实际截图、字幕录屏和 Discord 文案，不把方案表里的功能写成已发布能力。

## 本轮已完成的源码调整

2026-10-15，本地改动尚未发布；公开的 v0.13.0 安装包不包含以下优化。

- **选取闭环已实现**：编辑侧栏「部件与图层 / 属性」页签、语义目录与搜索、展开收起、当前范围修改标记、双向选择同步、装饰原有管理入口。画布外有父级路径；右键 / 手机「内外层」提供已知部件候选，悬停用不同于选中状态的细虚线。
- **视图工具已实现**：V 选择、H 手形平移、B 原生浏览；空格临时平移、定位、适合窗口与 100% 快捷键、可见快捷键帮助。视图操作不写入工程。手机选取后回到预览，工具区继续留在预览外。
- **视觉整理已实现**：石墨灰工具面板、统一蓝色选取反馈、细分隔线、紧凑按钮与矢量工具图标；收起重复的场景 / 反馈操作。390px、320px 桌面浏览器窄屏检查中，常驻工具区约 115px；触摸设备使用更大的点击范围。
- **仍未实现**：装饰多选 / 框选、对齐分布、对象吸附参考线、样式复制等条件性能力。当前目录为语义导航，并非通用自由图层编辑器。
- **构筑辅助已实现**：属性里的尺寸值对照和按部件还原当前范围；装饰九宫格贴边与向内距离；九切片原图分区、四边编辑、边缘延展方式与随容器伸展。真实消息可定位双方短文及长文顶部／中段／底部；旧样本不自动覆盖。操作说明见 [装饰配方](decorations.md) 和 [直接编辑](direct-editing.md)。

- 修复用户与角色内部部件混改：拾取自动区分双方的头像、正文、名字等部件，属性、画布、蓝图和导出使用身份明确的规则。旧通用 ID 保留在“全部消息”组。此修复优先于图层树等新增工具。

- 统一工作台的画布工具栏移至酒馆预览外，手机切换编辑页时隐藏；直接使用原工具控件，保留同一份蓝图和历史。独立示例预览保留内部工具条作为回退。
- 移动圆点 18px、尺寸方点 10px，细选框；两者保持约 40px 屏幕点击范围。缩放显示时补偿点击范围，小部件及视口边缘的两个把手分开。
- 进入画布暂时隐藏评论标点，退出恢复，避免标点阻挡选取。
- 预览缩放增加 50%、75%、100%、125%、150%、200%；适合窗口保持原有语义，不改变真实视口及断点。
- 修复缩放后的 iframe 容器因焦点而内部滚动、导致画面顶部被裁剪的问题。

验证结果见 [本轮画布验证](validation-canvas-ux.md)。

## 参考依据

Photoshop 的 [图层选择](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/transform-manipulate-layers/select-layers.html) 同时提供图层面板、画面自动选择和位置候选；[移动图层](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/transform-manipulate-layers/reorder-and-move-layers.html) 支持方向键 1px、Shift 10px。这里借鉴稳定的选择反馈和微调习惯；网页的父子布局及 CSS 范围需要另行处理。

Figma 的 [工具栏](https://help.figma.com/hc/en-us/articles/360041064174-Access-design-tools-from-the-toolbar) 区分移动、手形与缩放工具；[选择规则](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects) 说明嵌套对象、多选和框选；[缩放与视图](https://help.figma.com/hc/en-us/articles/360041065034-Adjust-your-zoom-and-view-options) 提供独立视图控制。这些交互适合逐步引入，先把选取和浏览分开。

Figma 的 [图层锁定](https://help.figma.com/hc/en-us/articles/360041596573-Lock-and-unlock-layers) 可防止画布误操作，同时保留面板选择入口。本项目装饰锁已阻止属性写入，应保留现有语义；若增加原生部件的编辑锁，需要单独说明作用范围。
