# 固定作品目录

日常从「作品」开始：选择已有作品继续编辑，或「新建作品」从空白开始、接入酒馆保存的主题、导入主题 JSON。新美化拥有独立工程、目录、素材和定稿，旧作品留在原位置。切换前自动保存恢复点，不需要手工导出再导入。

编辑时自动保存草稿；满意时用「保存定稿」留一个阶段版本，之后微调会显示「有定稿后的修改」。「应用 / 导出」用于应用到酒馆或下载主题 JSON，不等于保存工程定稿。恢复快照和文件备份放在「备份」入口。

作品选择器列出同一作品父目录中的有效作品。工作台地址保持不变，连接器继续使用原连接；切换时更换会话和 token，旧页面的迟到写入会被拒绝，其他页面会自动读取新作品。启动位置会记住最后选择的作品。旧源码同步在离开时暂停，返回后核对再开启。

```text
theme-works/my-theme/
├── artwork.json          作品身份与原位置
├── source/               CSS、主题字段、素材和构建配置
├── workspace/            当前工程、微调、素材库、小票、快照和本机配置
├── versions/<版本ID>/    定稿：主题、工程、素材、绑定源码
├── references/           参考图与历史制作资料
├── previews/             验收记录
├── migration-report.json 原文件的 SHA-256 与保留位置
└── .git/                 原存档仓库（如果已有）
```

界面用名称和时间识别版本，目录中的 ID 保持稳定。旧存档兼容原格式，不用重新导出。「自动恢复与临时快照」保留原快捷恢复入口。

## 第一次整理

停止工作台服务，创建作品的父目录，从工具目录执行：

```powershell
node scripts/migrate-work.js copy "D:\path\studio\.local\native-lab" "D:\path\theme-works\my-theme"
npm start
```

迁移只写入全新目录，先取得原数据目录锁，再复制全部数据、当前作品的存档和独立源码，逐文件校验哈希与旧版本清单。运行锁和 runtime.json 不复制。原件不删除；副本完整落盘后才更新 `.local/workspace-location.json`，供启动程序和 CLI 使用。失败时未完成副本以 `.pending-*` 保留，启动位置不会指向它。

为避免丢历史，原数据目录中的其他工程快照和小票也完整保留。固定作品不能被其他身份的工程覆盖；不同作品从选择器切换。源码根目录覆盖整个工作台时拒绝整体复制，应先整理独立源码。

新建时核对作品名称，再点「创建作品并开始编辑」。同名主题也会创建不同目录，不覆盖已有作品。原始主题放在新作品的 `references/imported.theme.json`；内嵌图片提取到它自己的素材库。接入已有主题时，`source/` 预留给后续可维护源码，不绑定旧作品的构建；「从空白开始」则会自动准备基础源码、构建配置与实时同步。新作品确认完整后才切换；失败时保留原作品。导入其他作品的工程备份仍会被拦截，避免混用身份。

源码迁移后自动同步暂停。旧脚本可能依赖工具相对路径，需要核对依赖、成功构建并确认微调还在，再开启自动同步。旧任务和构建记录内的绝对路径保留供追溯；原位置仍保留。工作台之外的参考图和验收图需另行复制，迁移不猜测这些路径，也不复制浏览器内的起步想法。

## 通用主题构建

绑定配置可设置 `program: "$STUDIO_THEME"`、`args: []`；`root` 是源码绝对目录。源码使用以下文件，并全部纳入 `watch`：

- `theme.css`：可使用 `__NAME_ART__` 形式的图片占位符。
- `theme-fields.json`：酒馆原生主题字段，构建器填入 CSS。
- `assets.manifest.json`：`{"version":1,"assets":[{"placeholder":"__NAME_ART__","file":"assets/name.webp"}]}`。
- `studio.recipe.json`：可选的装饰与素材配方，自动参与监听；见 [直接编辑约定](direct-editing.md)。
- 对应素材文件或目录。

构建依赖由当前安装的工作台提供，作品无需引用工具内部相对路径。内部候选使用独立素材，保存定稿和导出会合并当前面板微调并内嵌本地素材；自定义构建程序仍兼容原绑定方式。

## 升级与恢复

- 停止服务后备份整个作品目录；升级程序保留 `.local/workspace-location.json`。workspace/ 是真实自动保存位置，不需要手工同步导出文件。
- 换安装目录或位置记录丢失时，执行 `node scripts/migrate-work.js select "D:\path\theme-works\my-theme"`，然后 `npm start`。应先停止原服务；`STUDIO_DATA_DIR` 仍优先，可用于独立测试和回退原数据目录。
- 作品目录丢失或身份不一致时拒绝启动，不自动创建空工程。服务运行时不要手改 workspace/project.json。
- 「恢复工程」仍只恢复工程并暂停源码；完整恢复请用「复制完整恢复给 Agent」，先保留当前源码再处理。
- 单个定稿不包含全部小票、快照、浏览器想法或外部构建工具。完整备份应保留整个作品目录。Git 只按选择提交定稿，不自动提交草稿或推送。

## 迁移验证（2026-10-11）

已使用本地作品验证迁入独立目录，原源码、数据目录和存档保留，旧 Git 提交和版本 ID 不变；参考图与验收资料另外复制入作品。通用构建的基础主题逐字段与原主题一致，恢复自动同步后 project.json 的 SHA-256 仍与原文件相同。迁移后通过作品页保存了新定稿。个人作品不随工具仓库或安装包发布。

这项迁移检查只覆盖存储与作品操作；0.10 的真实宿主直接编辑和持久化应用结果另见 [验证记录](validation-0.10.md)。实体手机或模型生成未覆盖。
