# 美化作品存档与回溯

工作台程序和你的美化作品分别保存。工具仓库维护工作台、连接器与文档；作品存档默认放在工作台同级的 `theme-archives/<工程ID>/`，每个作品可有自己的本地 Git 仓库，不自动关联或推送 GitHub。

## 日常怎么用

1. 开始一轮较大修改前，用「主题 → 保存 / 恢复版本」留一个快速快照。
2. 在虚构测试对话中微调、标点、让 Agent 修改并验收。
3. 满意这个阶段后，打开「主题 → 作品存档与回溯」，填写版本名称，可写一句这次改了什么。
4. 已绑定源码时默认包含源码。需要 Git 历史就勾选「同时提交到此作品的本地 Git 仓库」，点击「保存作品版本」。

平时拖滑块仍自动保存，不会每拖一次就产生 Git 提交。快照适合短期撤回，作品存档适合长期保留一个完整阶段。本地 Git 提交不需要 GitHub 账号；需要跨设备备份时，自行连接私有仓库并推送。

## 一个版本包含什么

```text
theme-archives/<工程ID>/
├── .studio-artwork.json              作品身份
├── .git/                            可选的独立 Git 仓库
└── versions/<存档ID>/
    ├── manifest.json                名称、说明、基线与文件 SHA-256
    ├── notes.md                     可读版本说明
    ├── theme.json                   含本地图片的原生主题
    ├── theme.css                    本次最终编译 CSS
    ├── project/manifest.json        包含全部面板微调的工程
    ├── project/assets/              工程引用的独立本地素材
    └── source/                     本次绑定源码与设计记录
```

工程、主题与源码在存档期间核对一致性。源码未构建、构建进行中或复制过程中发生变化时，包含源码的存档会拒绝发布。每次存档也会保留一个工作台快捷快照。没有绑定源码的工程可以保存工程与主题。

源码范围为构建绑定的 `watch` 文件及目录，另外包含存在的 `README.md`、`design-brief.md`、`studio.build.json` 和许可证说明。应把维护所需的 CSS、字段 JSON、构建脚本和生产素材都加入监听范围。外部构建程序、工作台工具及 `node_modules` 不复制；原始大图等未纳入监听的文件仍由你自己的源码备份保留。源码限制 4900 文件 / 128 MiB，单次存档限制 5000 文件 / 512 MiB。

本地素材会保存字节；原有公网图片、字体或样式表外链保持引用，并在结果中提示，所以普通存档不保证完全离线。需要完全离线主题时另用严格离线导出。

## 怎么回溯

- 「核验文件」检查清单、工程身份和文件哈希。损坏或越界文件会拒绝恢复。
- 「恢复工程」先保存当前工程的恢复快照，恢复这一版全部面板微调，并暂停源码自动同步；可使用撤销返回。
- 有源码的版本提供「复制完整恢复给 Agent」。Agent 核验后先备份当前源码，再从该版本的 `source/` 恢复该作品源码，核对构建依赖和工程覆盖后恢复同步。工程恢复本身不会直接覆盖源码，避免下一次构建把旧工程冲回新版源码。
- 也可从 Git 的版本目录取回所需文件；不要在服务运行时覆盖 `.local/project.json`。本轮存档只包含当前作品版本，不包含其他历史快照、小票、浏览器想法或本机执行配置；完整服务历史仍需另备份实际数据目录。

Git 未安装、未配置提交身份或提交失败时，完整作品版本仍保留，界面明确显示 Git 失败。修好 Git 配置后，在该版本点击「本地 Git 提交」重试，不必重新导出。提交只包含选中版本与作品标记，保留其他已暂存文件。

可在「更改存档目录」填写空目录或同一工程已有的存档目录。工具目录、运行数据目录、源码目录和其他作品目录不能被当作当前存档目录。更换目录只改变此工程之后使用的位置，不搬动或删除原存档。

## Agent / CLI

```powershell
$env:STUDIO_URL = 'http://127.0.0.1:19323'
node scripts/cli.js artwork-status
node scripts/cli.js artwork-save '阅读布局定稿' --note '修复页面宽度与悬浮按钮' --git
node scripts/cli.js artwork-verify <存档ID>
node scripts/cli.js artwork-commit <存档ID>
node scripts/cli.js artwork-restore <存档ID>
```

`artwork-config <绝对目录>` 设置此工程的位置；`artwork-save ... --no-source` 明确只保存工程与主题。CLI 与 UI 都使用同一服务队列、当前会话与工程基线。Git 提交不会接受来自小票评论的任意 shell 命令，也不自动推送。
