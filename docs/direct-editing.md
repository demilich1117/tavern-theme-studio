# 直接编辑与简单工作流

入口仍然是「编辑 → 拾取元素」。点消息正文、头像、引用、输入框等原生部件后，在原来的属性面板调整；不需要先认识 CSS 或装饰配方。

0.14.0 提供「部件与图层 / 属性」页签：搜索中文名称、沿容器展开，或在画布中右键选择内外层。目录显示当前范围的修改标记，选中结果与属性、画布同步。手机从预览外「部件」进入，选好自动返回预览。具体视图与快捷键见 [画布工具](canvas-mode.md#选择与视图工具0140)。

**0.14.0 已修复用户 / 角色混改。** 拾取用户消息内的头像、正文、名字、时间戳等部件，会选中对应的“用户…”对象；角色消息同理。同类联动只限同一身份，仍遵守当前尺寸范围。对象下拉框分为页面与输入、角色部件、用户部件、全部消息通用样式。

旧版 `avatar`、`message-text`、`name` 等通用规则保持原有含义，界面明确显示“全部消息 · …”，仅在主动选择该组时同时调整双方。旧工程不会自动猜测并改写原有意图；只改一方时使用身份部件，必要时在通用组还原过去的共同修改。此修复随 0.14.0 提供，旧版 0.13.0 未包含。

需要直接摆位置和尺寸时，打开[画布模式](canvas-mode.md)。画布与这里共用对象、属性、编辑范围、保存和撤销；多部件蓝图、评论及截图也沿用同一工程的小票流程。

- 不支持的位置不会再回退为「全局界面」。画面会提示继续选择或按 Esc 退出。
- 当前对象旁边可直接进入相关的内层、外层部件和已接入装饰。窄屏拾取后自动切回编辑页。
- 数字既能拖动也能精确输入。颜色支持透明度和八位十六进制；改颜色保留原透明度。「分别调整四边」只在需要时展开。撤销按钮和 Ctrl+Z 对滑块、颜色控件有效；文字输入保持浏览器原有撤销习惯。
- 名字、时间戳和头像会隐藏不适合它们的属性。已有覆盖仍能显示和还原，不丢失旧工程设置。
- 属性下方显示实际生效状态。继承、其他断点、主题高优先级规则仍可能影响结果，可以展开「技术详情」诊断。
- 部件、布局和装饰共用尺寸范围；当前宿主未进入所选尺寸时会提示。设计工作台顶部可切换真实酒馆视口；「适合窗口」只缩放显示，不改变断点。预览尺寸与修改范围分别选择。
- 主题图片中的「调整装饰」「打开素材库替换」携带选中的对象。一个图片用于多个变量时仍需选择具体位置，避免误改其他位置。
- 窄屏使用「预览 / 编辑」切换，保留完整预览空间；画布工具条显示当前部件、范围和蓝图数量，蓝图撤销 / 重做直接可用。详细属性仍在编辑页，没有第二份编辑状态。

## 新建与保存

「作品 → 新建作品 → 从空白开始」只需填写名称。工作台自动创建基础主题、独立作品目录、源码与同步配置。源码维护者编辑 `source/theme.css` 和 `theme-fields.json`，用户继续在原来的属性面板微调。

「应用 / 导出 → 应用到酒馆」将本地素材内嵌后，走酒馆原生导入和主题选择流程；成功后主题会持久保存。默认生成新名称，同名时要求换名，保留原主题。宿主的外部样式导入提示照常显示。连接器不支持直接应用时仍可下载原生 JSON。

自动保存是当前草稿；「保存定稿」是可回溯的作品版本；「应用到酒馆」是当前酒馆实际使用的主题。继续编辑并不会自动覆盖已应用的主题。

## 源码维护约定

通用构建器 `$STUDIO_THEME` 支持可选的 `studio.recipe.json`。它会验证并写入构建清单，源码同步沿用已有规则与图层微调。配方 ID 和插槽 ID 必须保持稳定；已有素材、变量、装饰的归属继续由配方声明，不能把任意 CSS 图片自动当作可拖动图层。

配方文件自动参与通用构建器的监听与指纹计算，旧绑定也适用。无配方的老主题继续兼容；非法配方使候选构建失败，保留上次有效预览。

实现分工：`public/inspector.js` 管属性交互，`shared/editing.js` 管颜色/间距/尺寸的纯函数，`connector/picking.js` 管宿主拾取，`connector/native-theme.js` 隔离原生导入适配。工程历史、CAS 校验、源码合并与素材导出仍沿用现有服务。

本轮是有限部件的直接编辑，不表示所有第三方扩展、消息 iframe 和复杂伪元素都能任意点选修改。
## 尺寸覆盖说明（0.14.0）

属性面板新增“尺寸覆盖”折叠说明：显示当前编辑范围、真实画面宽度、命中的断点，以及已修改属性的基础值／此尺寸值／画面计算值。基础修改会被命中的同部件断点覆盖；没有填的属性沿用基础或原主题。画面值还可能受共同部件、高级 CSS、宿主和扩展影响，不把本工具的规则顺序误当成完整 CSS 优先级诊断。

“还原此部件的此尺寸修改”只删除选中部件在当前范围的规则，可以撤销，不修改另一方消息或其他尺寸。预览缩放不改变断点，真实画面宽度才决定命中哪个尺寸。
