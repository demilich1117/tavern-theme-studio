# 设计与技术取舍

## 工作台

使用者是准备制作或微调主题的酒馆用户。主操作是选择部件、调整属性、观察效果，随后导出。界面将预览放在中央，部件列表 224 px、属性栏 304 px。工作区使用炭灰、石墨、浅灰字和琥珀色选中态；4 px 间距基准、低对比边界和紧凑控件让聊天预览占主要面积。

领域词汇：主题、部件、消息、气泡、底层样式、继承、覆盖、手机范围、原样比较。特征是部件选择、预览拾取、匹配数量、选择器和属性状态互相对应。采用编辑器结构，避免以统计卡片、营销介绍或纯代码窗口占据工作区域。

## 工程模型

原主题完整保留为 `baseTheme`；受控修改保存到 `rules.base` 与 `rules.mobile`；高级 CSS 放在最后。导出时保留原主题字段，把生成 CSS 追加到原 CSS。输入校验只允许已知部件和属性。将结构化规则与 CSS 分开，保证属性可继续编辑而不需要逆向任意旧 CSS。

0.2 将变量编辑保存为 `variableEdits`，只替换基础 CSS 中对应声明的值范围。解析器识别字符串、注释、括号和块边界，不将重复名称、局部声明、媒体条件合并为全局变量。替换基础主题时清空位置绑定，可通过撤销或命名快照恢复。当前 schema v3 使用稳定工程 ID、变量锚点、配方图层与命名断点；旧 v1/v2 工程在保存迁移日志后升级。

通用性以标准宿主结构和独立样本验证；当前用户主题不是默认样式或正确性标准。`examples/starter.theme.json` 是独立编写的起点。变量面板采用非模态侧板，编辑时保留预览；快照和诊断使用可滚动对话框。窄屏属性栏改为单列。

工作台使用 Node.js 服务与浏览器 ES 模块。服务端通过固定版本 css-tree 解析完整 CSS 依赖，浏览器与连接器不新增运行框架。原子文件替换、revision 检查、统一历史和 SSE 构成界面/CLI 一致性。无需构建工具即可运行；连接器打包复制同一份核心，不维护第二套规则。

## 真实预览

跨来源的酒馆页面不应假定能够被嵌入或直接访问 DOM。由宿主连接器嵌入工作台编辑面板，或打开独立工作台窗口，使用精确 origin、窗口身份和随机 session 验证消息。宿主负责计算实际样式、按已知部件拾取，并将经过校验的工程编译为临时样式。拾取时停靠面板暂时收起，避免挡住目标。工作台保持独立，不读取聊天正文。

连接器导出快照使用 `/scripts/power-user.js` 的 `getThemeObject`，内部导入集中在适配入口。生命周期按目标 1.19.0 核验。预览不写主题，不重排 DOM，不调用生成 API。停止、断开、页面卸载均清理监听器、观察器、轮询、样式和拾取边框。

## 后续可扩展点

已加入素材管理、Hub 锁定、复制交接、可选 CLI、依赖导出与冻结验收快照。后续按真实制作反馈补充原生主题开关预览与适配器。自由布局与组件交互需要单独适配，不把 CSS 主题编辑伪装成任意界面搭建器。

## 0.8.1 一致性与验收

数据目录锁在迁移与任务恢复之前取得。工程命令仍使用会话、工程 ID、revision、指纹和单队列串行提交；素材索引与 Hub 缓存拥有独立写队列，跨请求导出也不会丢索引。不可变素材以 SHA-256 命名，项目锁定引用优先于当前远端目录。暂不引入数据库或前端框架。

小票领取和提交各保存工程快照，差异明确标记为这段期间的工程变化，不能假称全部由单个 Agent 造成。历史票缺失提交快照时如实说明。证据仅开放本项目 output 下小票明确列出的图片和文本，拒绝越界与主动内容。提交后工程指纹改变会要求用户核对当前效果再验收。

验收延续石墨底色、琥珀操作色、Segoe UI 字体和 4px 间距。修改摘要与验收操作优先，变更及证据用原生 details 按需展开；图片只在用户展开后加载。窄屏采用单列证据，操作区最小 44px 点击高度。
