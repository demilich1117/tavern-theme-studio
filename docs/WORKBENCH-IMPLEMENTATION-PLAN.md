## 1. 目标与已经确定的选择

最终操作流程：

**打开真实酒馆测试页 → 选择工程 → 选素材 → 调整装饰和布局 → 标点评论 → 把小票交给 Agent → 实时查看修改 → 验收或撤销 → 导出主题。**

已经确定的选择：

- 以真实 SillyTavern、工作台和专用虚构测试对话作为默认制作与验收环境；不再新建独立聊天预览页。旧发行演示保留。
- 主项目保持现有 Node.js 22+、原生前端和连接器架构，不引入酒馆服务端插件，不顺便改酒馆核心。
- 首个完整样本是「月誓 · 龙廷 2.2.4 — 月弧浮页」。通用编辑器不能硬编码这一主题的名称、素材或选择器。
- Agent 接入采用**通用本机 CLI**，不绑定某个模型厂商或 harness。
- **用户将小票复制到已打开项目的 harness 对话，是正式支持的默认交接方式。** 这条流程应先完整可用；自动启动 CLI 是后续便利功能，不是制作主题的前提。
- 源码修改、工作台属性编辑与 Agent 操作必须进入同一套工程与版本检查机制。
- 既有内嵌版和外链版 2.2.4 发行目录作为恢复基线保留；开发与自动构建写入候选目录。
- 保留原生发送、停止、折叠、编辑、swipe、抽屉等行为。装饰默认不接收指针事件。

### 复制小票现在是否可用

可以。现有版本已经提供复制单票、复制交接说明、CLI 领取、结果回写和 UI 验收。接收小票的 harness 需要能够访问该项目及正在运行的本机工作台；仅能访问云端文件的 session 不一定能连接本机 `127.0.0.1`。

0.5 已提供「复制给 Agent」的一次完整交接：工作台地址、源码与工具项目路径、指定单票/选票、快照、定位、CLI 命令和验证要求。纯 JSON 复制继续保留。浏览器不允许直接复制时可手动复制完整文本。

自动派发不能成为基础功能的阻塞项，也不能把“复制成功”描述为“Agent 已经开始执行”。

## 5. 共用设计规则

### 5.1 工程、源码与界面修改

- 源码构建生成基础主题；工作台调整单独保存，包括变量、部件、装饰、响应式配置和高级 CSS。
- 工程拥有稳定 `projectId`；本机源码绑定独立保存，不把绝对路径、执行程序或凭据带入分享文件。
- 使用源码指纹、工程 revision 和运行会话标识判断结果是否过期。不能只靠会重置的 revision 判断跨重启状态。
- UI、CLI 和自动构建通过同一命令队列提交。校验或磁盘持久化失败时，不推进内存工程和历史。
- 源码刷新是更新基础主题并合并最新调整，不是把构建产物无条件整包覆盖到当前工程。
- 变量优先使用配方中的稳定绑定 ID；对普通导入主题，按变量名、选择器、媒体条件与声明上下文唯一匹配。歧义必须显示，不猜测映射。
- 编译顺序有明确规则：基础主题及变量修改 → 受控部件/布局/装饰规则 → 用户高级 CSS。诊断显示可能覆盖关系。
- 恢复工程快照与回退源码是不同动作。恢复预览时暂停自动覆盖，直到明确继续同步；不能马上被 watcher 再次覆盖，也不能暗中回滚源码。
- 新字段和桥接消息进行版本协商；旧连接器缺少能力时给出更新提示，不能把无效果的操作显示为成功。

### 5.2 装饰与原生主题导出

- 图层是编辑模型，不意味着必须向酒馆插入永久 DOM。
- 原生主题模式只编译为原生字段和 CSS；支持背景、可用伪元素、九切片等可复现方式。
- 先检测与声明插槽所有权，再使用 `::before` / `::after`。不能破坏原主题或其他扩展已有内容。
- 任意 CSS 不能自动逆向成完整图层编辑器；主题配方负责声明可编辑关系，未识别部分保留源码/CSS入口。
- 实际装饰默认 `pointer-events: none`；编辑框和拖拽手柄单独隔离，结束编辑后清理。
- 原生主题模式的效果必须在工作台和连接器关闭后仍可导入复现。确需运行时 DOM 的效果明确作为伴生扩展能力，不能伪装成纯主题。

### 5.3 素材与公开链接

- 引用记录包含来源、素材 ID/哈希、图集、版本和固定链接。更新图片创建新内容地址，不覆盖旧文件。
- 预览地址、本地已提交、远端已推送、Pages 已部署和图片实际可访问分别处理。
- 发布用链接至少检查状态、类型与可用字节；固定版本可用时核对内容哈希。
- 工作台前端通过本机服务读取已配置素材源，避免让浏览器直接跨域携带本地服务凭据。不要为联动开放任意外站写接口。
- 目录缓存可在离线时显示，但未缓存的图片不能冒充可用。
- 既有代码与 12 张素材的公开发布已经完成；未来新增内容按其具体发布范围处理，本地开发不等于自动推送。

### 5.4 小票与 Agent

- 小票意见是待处理数据，不是执行任意命令的授权；只在用户交付的项目和任务范围内处理。
- 用户复制给已打开项目的 harness 后，Agent 应先读取当前服务里的单票与快照；剪贴板中的 version/revision 可能已过期。
- 小票状态与执行任务状态分开。进程退出码为 0 不等于用户已验收，也不等于视觉验证完成。
- 本机 API 不提供通用截图或任意页面脚本执行。视觉验证使用 harness 已有、获授权的浏览器能力，并先确认虚构样本状态。
- 没有浏览器能力时，可继续完成源码与相关检查，但结果必须写明视觉验证尚未完成。

## 8. 必须覆盖的失败场景

| 场景 | 预期行为 |
| --- | --- |
| 源码构建中又保存新版本 | 只接受最新源码对应结果 |
| 构建期间用户调整属性 | 合并最新调整，不覆盖用户操作 |
| CSS/素材构建失败 | 保留上一次成功预览，显示可定位错误 |
| 变量同名或结构变化 | 无法唯一匹配时要求处理冲突，不猜测 |
| 服务重启后收到旧写入/结果 | 会话/指纹/版本不匹配时拒绝 |
| 用户恢复旧快照 | 暂停自动应用，避免 watcher 立即改回 |
| 图层目标或伪元素失效 | 显示不可用与修复入口，不静默覆盖原效果 |
| Source Hub 离线 | 显示缓存和缺失状态，已锁定引用不被改写 |
| 素材已本地提交但未推送 | 不显示为已可公开发行 |
| 旧素材归档 | 旧 URL 与已有主题继续可用 |
| 两个 Agent 领取同一票 | 只允许一个成功领取 |
| CLI 超时/取消/异常退出 | 状态可恢复，已产生修改保留供核对 |
| 无浏览器验证工具 | 结果标记视觉待验证，不假称验收完成 |
| 离线导出缺外链字节 | 列出缺失依赖，不生成误标为完整离线的结果 |
| 大工程超过单 JSON 请求上限 | 使用分文件恢复流程，不要求盲目放宽所有限制 |
