## 检查结果

- `npm run check` 通过；`npm test` 全部 **119 项通过**，含小目标、边缘及缩放点击范围、身份选择器、旧通用规则、独立蓝图、语义导航完整性与身份搜索检查。
- 独立 SillyTavern **1.19.0**、虚构测试对话、独立工作台数据。使用云间主题样本，只在隔离数据中修改和应用，没有更改作品源码或用户正在使用的酒馆。
- Chrome 页面尺寸 **390 × 844、320 × 640、844 × 390、1600 × 1000**：工具栏在酒馆 iframe 外；页面不横向溢出；移动与尺寸把手点击范围互不重叠，测量约 **40px**。
- 外部工具栏：模式切换、蓝图备注、撤销 / 重做、退出后隐藏、手机预览 / 编辑切换通过。新增导航工具后，桌面收起状态约 73px；390px、320px 桌面 Chrome 窄屏的实际布局约 115px；触摸命中使用更大的尺寸，蓝图与展开工具的高度随内容变化。
- 固定缩放 **50%、200%** 与适合窗口：宿主视口仍为 390px，点击范围维持约 40px。鼠标在屏幕移动 16px，在 50% 下写入 32px、200% 下写入 8px；都可撤销回原值。
- Shift + 方向键调整头像宽度 **10px**，撤销恢复；拖动中按 Esc 取消且不提交，均通过。
- 焦点导致缩放 iframe 内部滚动的问题已复现并修复，预览顶部和底部恢复完整。
- 浏览器记录无错误；本轮保留宿主自身的一般警告，没有发送真实消息或调用模型。

## 用户与角色身份隔离

修复前真实复现：拾取用户头像得到旧目标 `avatar`，拾取用户正文得到 `message-text`；移动后均修改 **2 条用户消息和 8 条角色消息**。消息外框已有身份选择器，内部部件仍共用规则是混改原因。

修复后，手机视口的“仅手机”范围与电脑视口的“所有尺寸”范围共 **16 组** 检查通过：双方的头像、正文、名字、消息外框分别移动，用户目标改动数为 2、角色目标为 8，对方改动数均为 **0**。头像尺寸分别调整与撤销通过；主题过渡完成后检查恢复值。

真实鼠标拖动用户头像、属性面板将用户正文字号改为 21px，通过检查，角色对应样式保持原值。界面下载的主题 JSON 仅生成手机条件下的 `user-avatar` 与 `user-message-text` 覆盖，选择器包含 `is_user="true"`；完成后撤销至原工程指纹。

同一张蓝图分别保存 `user-avatar` 与 `assistant-avatar`，保留两个目标、各自选择器及范围，工程指纹不变。旧通用 ID、规则与小票序号语义保留，不自动推测旧修改属于哪一方。

导航修订后的核心包 **496 个文件**、连接器 **37 个文件**。打包、哈希与导入图验证通过；解压启动、命令、导出、重启、一键安装、重复启动、后台关闭、卸载预览和用户数据保留的烟测均通过。本地包沿用 0.13.0 版本号，不代表公开发行版本已更新。
