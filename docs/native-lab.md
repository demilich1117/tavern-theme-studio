# 在真实酒馆里修改与验证主题

0.8 接续仍使用本流程。候选原生导入可启动同版本酒馆的独立 `--dataRoot` 与 `--configPath`，只安装测试连接器和虚构对话，关闭预览后通过原生文件输入导入；不要复制用户聊天或设置。真实发送测试可使用只返回固定虚构文本的本机响应服务，不能把这种测试写成真实模型/流式验证。结果和限制见 [0.8 验证](validation-0.8.md)。

0.3.0 起，把正在使用的 SillyTavern 当作预览宿主。工作台仍负责工程、变量、CSS、撤销、快照与导出，连接器负责在真实宿主临时应用样式，浏览器工具负责操作和截图。无需重新搭一个聊天模拟页面。

## 启动

新主题或整体改造先走 [从零共创](co-design.md)：认识当前宿主 → 设计简报 → 视觉参考与方向选择 → 原生样板。下面的启动与测试流程既用于采集构思依据，也用于样板和最终验收；概念图和示例预览不能替代宿主检查。

先启动原来的酒馆，更新已安装的工作台连接器，再运行：

```powershell
npm ci --omit=dev
npm run package:connector
npm run lab
```

`package:connector` 只打包。将 `dist/tavern-theme-studio-connector/` 的文件更新到原连接器目录；更新前备份。已有私人酒馆标签不需要刷新，新开测试标签会加载新版。

`start.cmd`、`npm start` 与 `npm run lab` 共用同一启动入口；已有同目录服务可直接复用。`lab` 默认在 `http://127.0.0.1:19323` 启动工作台，工程与快照存放于 `.local/native-lab/`。文件参数只在这个目录尚无工程时作为种子；之后不会覆盖已有修改。首次也可传 `examples/starter.theme.json`，不依赖未生成的 dist。可设置 `STUDIO_PORT`、`STUDIO_DATA_DIR` 和 `TAVERN_URL`。关闭该进程即停止测试服务。

默认本机酒馆入口：

[打开原生测试工作台](http://127.0.0.1:8000/#tts-lab=&studio=http%3A%2F%2F127.0.0.1%3A19323)

也可以在酒馆「扩展 → 主题工作台」点击「在新标签打开测试工作台」。该链接采用地址框内的工作台地址；连接器默认地址为 19323；高级独立服务 `npm run start:standalone` 使用 19321。

专用测试标签在酒馆准备完成后创建／读取测试对话并连接停靠面板。准备期间遮住聊天区域；失败时显示错误与重试按钮。酒馆 1.19.0 会恢复共享输入草稿，专用测试标签等待其 300ms 保存防抖完成后只清空本页输入 DOM，不触发输入事件，也不改写共享草稿存储。普通「打开测试对话」仍拒绝在有草稿、消息编辑或生成时切换。

## 测试内容

角色名为「主题工作台 · 测试角色」，用户消息署名「测试访客」，头像与附件来自连接器自己的素材。首条消息明确说明虚构来源。

| 入口 | 样本 |
| --- | --- |
| 普通对话 | 系统说明、用户／角色消息、名字、头像、时间戳、中文／英文／emoji |
| 引用与排版 | 标题、粗体、斜体、删除线、行内代码、引用、列表、分隔线、链接 |
| 代码与表格 | 原生 Markdown 代码块、复制按钮、长代码行、表格 |
| 思考折叠 | 人工占位文本、原生折叠与编辑、时长与 token 计数样本 |
| 图片与附件 | 本地示意图、原生媒体区、文本附件与查看入口 |
| 长文滚动 | 十四个长段落，供检查行宽、遮挡和滚动 |
| 候选回复与编辑 | 三条预置 swipe、原生切换选择器、消息编辑／取消 |

「打开测试对话」复用已有样本及其编辑；「新建测试副本」创建新聊天文件，旧副本保留。通过角色与聊天元数据标记识别归属，绝不按显示名去覆盖角色。准备期间切换聊天会中止后续操作。

侧栏、原生设置、消息编辑、思考展开等状态直接操作酒馆控件。「收起面板」保留实时连接并露出完整宿主，「显示工作台」展开。手机面板占满屏幕时先收起，再观察真实消息。

没有连接模型时，酒馆可能禁用左右箭头；可点 `1/3` 打开原生 Swipe Selection，再选已有回复。不要向最后一个 swipe 之外切换来测试美化。流式生成／停止、群聊、消息 iframe、工具调用和第三方扩展特殊组件需单独准备场景；不能把这十条静态样本称为覆盖所有状态。

## 修改、预览与保存

真实宿主临时预览保留原生页面宽度滑块对 `--sheldWidth` 的控制，不用工程 `chat_width` 强制覆盖。主题 CSS 应沿用该变量并仅限制实际导航避让空间；模拟预览和原生导出仍使用主题的宽度字段。宿主 1.19.0 的滑块在松手时应用宽度，键盘修改数值后需完成宿主应用操作再测量。

1. 打开测试链接，等标题和工作台状态都显示原生测试对话。若已有工程与宿主主题不同，关闭「读取当前主题」弹窗可保留工程。
2. 在「主题 → 保存 / 恢复版本」保存一个版本。通过真实面板拾取元素、改变量／部件；复杂修改在主题源码完成。
3. 在「源码同步」绑定配方并开启自动同步。保存源码后候选构建合并最新界面调整，SSE 推送到编辑器并临时应用到真实酒馆。失败保留上次效果；无需手动导入构建工程。
4. 检查受影响的测试内容和原生交互。响应式测试读回实际 `innerWidth/innerHeight`；收起面板检查全部阅读区域。
5. 撤销测试数值或恢复快照，核对实际计算样式。需要交付时导出，持久化应用仍走酒馆原生导入／更新流程。

```powershell
$env:STUDIO_URL = 'http://127.0.0.1:19323'
node scripts/cli.js snapshot-save '本轮修改前'
node scripts/cli.js set assistant padding 24px
node scripts/cli.js undo
npm run build:folio -- --no-preview
node scripts/cli.js build-presets
node scripts/cli.js build-preset 0
node scripts/cli.js build-auto on
```

制作时直接使用 build-preset / build-auto，前面的手动 build:folio 命令只是兼容示例。自动构建固定写入候选目录，不更新现有 2.2.4 发行文件，也不生成独立预览。`--no-preview` 的手动兼容入口保留旧演示。恢复快照会暂停自动应用；本机源码绑定和迁移恢复位置见 [源码同步](source-build.md)。本机 API 不读取酒馆私人消息，也没有任意执行页面 JavaScript 的命令；实时 DOM／截图由浏览器工具按本次任务范围获取。

0.5 测试服务仍沿用 `.local/native-lab`。启动前验证已有 runtime 的地址与服务可达性，复用可用服务；更新服务需发现当前 PID 并核对启动命令。仅刷新专用测试标签加载更新后的连接器。v3 能力协商失败会明确提示升级，打包本身不代表宿主安装完成。

## 当前宿主依据

已核对本机 SillyTavern 1.19.0 / `06bde939f` 的 `getContext`、角色创建接口、原生聊天保存格式、`selectCharacterById`、`openCharacterChat`、reasoning、media、files 与 swipe 元数据。内部导入限于适配层。官方入口见 [UI Extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/)。其他版本需要重新核对。

原生测试对话减少了美化工作接触私人内容的需要；它不代表浏览器权限、登录和自动审批的规则被取消。测试页仍加载用户安装的扩展，第三方扩展的自动行为与设置需按实际环境判断。
