# 从零与 Agent 共创酒馆美化

只有一句「想做一个属于自己的酒馆」也可以开始。先和 Agent 认识真实界面，把想法变成可以比较的图，再把选中的方向做成能阅读、能操作、能继续编辑的原生主题。

工作台里打开 **「从零共创」**，只需说个大概：**想做什么主题、主要用电脑还是手机、布局能改多大**。例如「想做暗黑童话主题，手机为主，布局可以大改」已经足够。复制给已打开本项目的 Agent，让它提出方案，边看图边补细节。还没安装时也可以先用本文末尾的开场提示讨论；操作环境按 [普通用户入门](../README.md#beginner) 准备。

喜欢先看图的用户，可以先读 **[DOUBLECHEESE 六格共创漫画](comic-guide.md#page-3)**，再按本文逐步制作。

工作台提供简报和交接文字；聊天、看图和生成图片在你使用的 Agent / 图像工具中完成。复制不会自动启动模型，也不会自动附带参考图片，需要在同一对话中提供图片文件。

## 一条可以反复回看的路线

```text
认识宿主 → 写设计简报 → 用图探索与比较 → 记录选定方向
    → 做一小块原生样板 → 扩展完整主题 → 多状态验收与交付
          ↑ 发现布局不成立时，回到对应问题继续讨论 ↑
```

| 阶段 | 用户和 Agent 一起做什么 | 留下什么，才值得继续 |
| --- | --- | --- |
| 认识宿主 | 查看虚构测试对话、界面部件与目标版本；区分新设计和旧主题改造 | 原始桌面 / 窄屏截图、界面地图、可改与需保留的部分 |
| 设计简报 | 用户只说主题、设备和布局意愿；Agent 随讨论补充具体建议 | 一句起步需求，逐步积累为设计记录 |
| 视觉探索 | 比较 2–3 个构图和阅读体验不同的方向，用参考图讨论 | 带编号的候选图、各自优缺点、取舍理由 |
| 方向收敛 | 选一个主方向，明确保留什么、修改什么、舍弃什么 | 选中图片版本、桌面 / 手机策略、样式与素材清单 |
| 原生样板 | 先做阅读面板、两类消息和输入区，再接入一种代表性装饰 | 真实酒馆截图、可恢复版本、与参考图的差异说明 |
| 完整交付 | 扩展到细节、抽屉和交互状态，逐项验收 | 主题 JSON、工程备份、源码 / 素材及验证范围 |

这是一条默认路线。已有清晰且选定的参考图，可以直接解释它如何对应宿主，然后做样板；只修圆角或某个遮挡，不必重新跑整轮图。探索中只补问会影响下一步的 1–3 个问题，Agent 可以先提出有依据的选择，让用户看图表达偏好。

## 1. 先认识酒馆，再发挥想象力

Agent 先读项目 `AGENTS.md` 和 [真实酒馆工作流](native-lab.md)，在 `#tts-lab` 专用标签确认「当前为虚构测试对话」，再读取画面。先保存「共创开始前」版本。没有宿主时可暂用界面示意和示例预览讨论，但标注哪些结构和状态尚未核验。

用普通语言向新用户介绍下列区域，再结合当前画面定位。选择器只是工作台的定位线索，具体结构以目标版本源码和实际 DOM 为准。

| 界面区域 | 设计时可以讨论什么 | 需要保住什么 |
| --- | --- | --- |
| 全局背景、阅读面板、聊天列表 | 空间感、正文宽度、背景与前景层次、留白 | 长文滚动、不同窗口高度下的可读区域 |
| 角色消息与我的消息 | 连续书页 / 气泡 / 分栏感、节奏、两类消息辨识 | 真实消息结构，短文与长文都能成立 |
| 头像、名字、时间和操作栏 | 视觉顺序、大小、对齐、边饰 | 名字可读、编辑 / 复制 / swipe 仍可操作 |
| 正文与 Markdown | 字号行高、强调、引用、代码、表格 | 正文对比、长行处理、代码复制与链接 |
| 思考折叠栏与正文 | 主次层级、展开 / 收起的形态 | 折叠和编辑行为，长内容适配 |
| 输入区及按钮 | 多行输入的呼吸感、按钮组织、边缘装饰 | 发送 / 停止的原生显隐、输入空间、点击范围 |
| 顶部菜单、设置抽屉与角色栏 | 材质延续、面板层级、密集控件排版 | 展开、锁定、收起、表单输入与焦点 |

主题改变宿主外观。角色卡内容、消息 iframe、助手脚本或新增功能需要另定交付物，不能在参考图里画出新功能就当作 CSS 能完成。工作台的「仅手机」默认是 767 px，但宿主可能有不同断点，实际验收要检查宿主阈值两侧。

**理解宿主不等于沿用当前布局。** 用户允许大改时，可以重新组织阅读区、消息呈现、头像名字关系、输入区和装饰空间。截图用来认识真实部件、内容和交互，不能把其坐标当作设计边界。Agent 要区分原生 CSS 能实现的排版与需要 DOM 重构或扩展开发的方案，既给大胆方向，也讲清实现方式。

### 从零设计，工程从哪里开始？

**新主题：** 设计从空白简报开始，技术上仍需一份有效的原生主题作为底层。在「主题 → 导入工程 / 酒馆主题」导入目标酒馆导出的干净基础主题，或包内的 `examples/starter.theme.json` 通用起点。通用起点带少量示例样式，不是最终设计，Agent 应逐项替换；原生字段格式和外观默认值仍需按目标宿主核对。已有工程会在导入前自动保存恢复版本。

**改造旧主题：** 用「接入酒馆当前主题」或导入旧主题 JSON，先列出要保留的布局、素材、字号和行为设置。不要把「换一种氛围」理解成重置全部偏好。

「从零共创」里的起点选项只记录意图，不会替换工程。新工程导入后，先前简报仍属于旧工程；先复制或下载，再在新工程中继续记录。`npm run lab -- examples/starter.theme.json` 的种子参数只对没有工程的数据目录生效，不能用它清空现有工程。

## 2. 一句话起步，细节边看边定

初次只需三项，不知道怎么选也可以让 Agent 提案：

| 用户说什么 | 例子 |
| --- | --- |
| 想做什么主题 | 「暗黑童话」「星际终端」「想要像一本魔法书」 |
| 主要在哪用 | 电脑、手机，或两边都用 |
| 布局能改多大 | 可以大改、保留大体布局，或看图再定 |

工作台默认收起「已有参考或特别要求？（选填）」。已有主题、参考图片、特别喜欢 / 不喜欢的东西、素材倾向可以补充，留空不影响开始。不要把阅读密度、素材清单或验收标准当作用户必须完成的问卷。

Agent 根据这些信息提出具体方向，解释每个方向的排版、阅读感受与手机取舍。长文习惯、必须保留的设置、外链偏好和验收条件，在出现相关选择时再补充；优先给建议或图，而不是一次抛出一长串问题。用户说「暗黑童话，手机，布局大改」时，就应先给可讨论的设计方向。

[设计简报模板](co-design-brief.template.md) 同样从一句话开始，后面的专业记录由 Agent 随讨论整理。工作台简报按工程保存在当前浏览器；它不属于 `.studio.json` 备份。换浏览器、地址或电脑前请「下载简报」，与主题工程一起保存。

## 3. 让视觉参考成为讨论依据

### 先做有区别的方向，再看图

Agent 先从简报提出 2–3 个方向，每个写清**空间构图、文字节奏、材质层级、标志性细节、手机取舍**。不能只把同一张聊天面板换成紫色、绿色、蓝色。每个方向都要解释它适合怎样的阅读习惯。

例如，同样是「月夜书房」，可以比较连续书页、批注手稿、轻量通讯笺：它们的消息分隔、头像位置、留白与装饰分布应有实质差别。风格隐喻必须映射到酒馆已有部件，Agent 同时说明可实现部分和需要验证的部分。

| 用什么图 | 回答什么问题 | 输入和约束 |
| --- | --- | --- |
| 氛围 / 材质板 | 用户还不确定喜欢哪种气质 | 少量色彩、纸张 / 金属 / 玻璃等材质与文字层次；明确它尚未证明界面可用 |
| 基于宿主截图的界面参考 | 这个方向放进酒馆后是否成立 | 虚构测试对话截图、相同视口与样本文本；按布局意愿重组空间，保留真实部件与可操作性 |
| 选定方向的局部放大与手机图 | 消息细节和装饰在小屏上如何取舍 | 选中图片版本、局部问题、明确的手机重排策略；不是简单缩小整张桌面图 |
| 独立生产素材 | 已决定的装饰如何实际使用 | 无文字 / 假按钮、尺寸与锚点、留白、必要的透明背景，按职责分层 |

第一轮通常只需 2–3 个可比较方向。有图像工具时，直接用真实宿主截图约束生成；尚在找气氛时可先做材质板，然后回到宿主构图。工具不能用时，给出可复制的出图提示，并用已有参考图或明确标注的线框继续讨论；没有实际产出的图不能写成「已生成」「已看图验证」。

### 一份可直接改写的出图提示

```text
请为 SillyTavern 原生聊天界面制作视觉探索图。本轮只解决：[构图 / 阅读密度 / 手机装饰取舍中的一个问题]。
起步想法：[主题关键词、电脑 / 手机、布局可大改 / 保留 / 待定]。
已知补充：[已有偏好或参考；没有可省略，不要求用户先填完]。
附件：[目标宿主的虚构测试对话截图；已有选中方向图的文件名 / 版本]。

以附件认识原生部件与功能，保留阅读面板、两类消息、头像名字、消息操作、
输入框及真实按钮的身份与可操作性；布局允许大改时重新组织空间和排版，
不锁定原图坐标。说明原生 CSS 能实现的部分与需要额外结构的部分。正文使用虚构内容。
输出 [2–3 个不同方向 / 已选方向的一处改进]，用独立编号标记，采用相同
视口和相近的样本文本长度。每个方向须在构图、排版、材质层级或装饰语言上有差异。
正文与输入区优先，重要装饰避开文字和点击区域；同时表现窄屏的取舍。
这是待讨论的概念图，图中文字、图标和控件不作为实际 DOM 或功能验收依据。
```

图像工具生成图片后，Agent 要把图展示出来，逐张解释具体设计决定和实现疑点，再邀请用户用「保留 / 调整 / 放弃」反馈。用户明确说「A 的书页结构 + B 的克制装饰」时，记录组合规则，先修选中的构图，不再每轮全图随机重抽。

比较时至少看：**是否符合氛围、长文读起来是否舒服、消息层级是否清楚、手机是否留足空间、原生控件是否能实现**。视觉图里的文字和图标可能失真，应回到真实控件核验；单张漂亮图片不能证明菜单、滚动和按钮能用。

## 4. 把选中的图变成制作说明

在简报中记录：选中图文件名 / 编号和版本、喜欢的区域、仍需改的区域、明确舍弃项、是否进入制作。已有选择沿用，不重复要求确认同一个方向。

Agent 从参考图提取这些可实现的决定：

| 决定 | 示例内容 |
| --- | --- |
| 排版 | 正文宽度、字号行高、消息间距、头像 / 名字 / 操作栏关系 |
| 视觉层级 | 背景、阅读面板、消息、抽屉的前后关系与对比 |
| 设计变量 | 文本 / 弱化文本 / 强调色、边框、圆角、阴影与间距；说明各自用途 |
| 素材清单 | 每张图的职责、透明需求、锚点、显示尺寸、手机替代方案 |
| 状态与限制 | 长文、多行输入、思考折叠、hover / focus、菜单展开及需单独验证的扩展 |

色板只是其中一项。复杂装饰先说明布局占用与层级，不能靠把正文缩窄来凑参考图。只有一张效果图时也不要把含假文字和按钮的整图铺成背景。

## 5. 先做一个能用的原生样板

先完成阅读面板、角色消息、我的消息、头像名字和输入区；加一处能代表风格的细节即可。保存「原生样板」版本，在真实测试对话检查桌面和窄屏，将截图与选中参考图并排比较。

如果实现偏离图，说明是宿主约束、素材不合适还是样式未完成，并给调整建议。布局尚未成立时先修样板，避免批量制作最后用不上的装饰。新主题中的 `chat_display` 等原生行为字段不随临时预览切换，相关效果要在原生导入后检查。

样板通过后再扩展正文、引用、代码、表格、思考区、菜单和抽屉。复杂主题保留可维护 CSS 和素材来源，通过 [源码同步](source-build.md) 或 CLI 导入到当前工作台；通用新主题要使用自己的源码，不必运行月弧示例构建器。

素材需要时才生成。背景、透明点缀、边框分别准备；核对真实 alpha、不同底色的边缘、裁切、清晰度和体积。已定稿图片原样保存，移动或缩小不等于重新绘制。通过「素材 → 素材库」上传生产资源，按职责接入变量 / 图层；记录来源和可分发范围。

## 6. 用小票迭代，再完成交付

方向讨论留在简报，具体位置的问题交给 **「标点评论 → 修改意见 → 复制给 Agent」**。例如：「保留 A 的输入框形状；手机上右侧纹饰减小，不挤压三行输入」。Agent 按小票快照核对基线、修改并回写证据，用户检查后验收。详见 [进阶协作](advanced-guide.md#agent)。

交付前共同检查：

- 长文、短消息、两类消息、Markdown、图片、思考展开 / 折叠、预置 swipe 与编辑状态。
- 顶部菜单和抽屉、输入区与多行输入、点击范围、键盘焦点；真实生成 / 停止需另备场景，静态样本不能冒充已验证。
- 桌面、窄屏与低高度窗口；读取实际视口，收起工作台看完整阅读区域。手机示意图不能代替实体手机与软键盘测试。
- 装饰不截获点击、不遮正文；原生宽度 / 字号等约定保留的控制仍然有效。
- 导出的新名称主题 JSON 在酒馆原生导入并选中后检查持久效果；同时备份 `.studio.json`、简报、选定参考与必要源码 / 素材。

把**概念图、真实截图、自动检查、实际验证的版本与未覆盖项**分别写清。只在模拟示例中看过时，如实保留这个限制。完整交付选项见 [验证与交付](advanced-guide.md#delivery)。

```text
我想用 tavern-theme-studio 从零共创一个 SillyTavern 原生主题。
请先读 AGENTS.md 和 docs/co-design.md，确认目标宿主和工程起点，
用虚构测试对话帮我认识阅读面板、消息、头像名字、输入区、思考栏和抽屉。

我大概想做：[主题关键词或一句话]
主要用：[电脑 / 手机 / 两边都用]
布局：[可以大改 / 保留大体布局 / 看图再定]

这些就作为起点，不必先让我填专业需求；有必要时只补问影响下一步的问题。
请提出 2–3 个构图、排版和装饰语言
不同的方向。用视觉参考图讨论，说明可实现性与手机取舍，不能只换色。

```
