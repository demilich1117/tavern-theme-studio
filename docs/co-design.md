# 从零与 Agent 共创酒馆美化

只要一句「想做暗黑童话主题，手机为主，布局可以大改」就能开始。你负责表达喜好和试用，Agent 负责理解酒馆、给图、整理选择和制作。

## 你只需要做三件事

1. **聊想法。** 直接告诉 Agent 想做什么主题、电脑 / 手机、布局能不能大改，不必先安装工具或填表。已有工作台时，也可以从「从零共创」点 **「复制给 Agent，开始共创」**，把工程信息一起带入对话；有参考图时另附。
2. **看图，直接说喜欢哪里。** 例如「喜欢 A 的书页感，装饰少一点」。Agent 会先认识酒馆部件，再给构图和排版有区别的方向，并把你的反馈整理下来。你不用回来记选图，也不用再复制制作提示。
3. **试样板，边看边改。** 大方向敲定后，Agent 尽量照选定参考图做出样板并接入工作台，让你比较实际效果。你可以「拾取元素」自己调字号、间距等，或用「标点评论」提意见后告诉 Agent「标好了」。想先试多个部件的位置，也可用「画布 → 蓝图 → 保存整张蓝图」，告诉 Agent「蓝图已保存」。Agent 接着落实，检查满意后「应用 / 导出 → 应用到酒馆」。

可以先看 **[六格共创漫画](comic-guide.md#page-3)**。还没安装时，先用 [文末开场](#可以直接发给-agent-的开场) 讨论，操作环境按 [普通用户入门](../README.md#beginner) 准备。

### 常见的小疑问

| 疑问 | 怎么做 |
| --- | --- |
| 已经在和 Agent 聊，还要填这页吗？ | 不用，直接继续。它只是开场时方便带入工程信息的入口 |
| 复制到哪里？ | 打开能读写本机项目文件的 Agent，让它打开 `tavern-theme-studio` 文件夹，再粘贴。工作台不会自动启动 AI |
| 必须填参考和细节吗？ | 不必。一句话足够；图片和特别要求选填，具体排版由 Agent 提案 |
| 看过图后需要手工记录吗？ | 不需要，直接在对话里说。Agent 保存选图、修改意见和进度，你不用填第二张表 |
| 换设备或换 Agent 怎么接着做？ | 让 Agent 给出最新设计记录与参考图，带到新对话；同时保留工程和源码 |
| 这页想法会消失吗？ | 按工程保存在当前浏览器，可展开「想法怎么保存？」下载。它不包含后续聊天，不会与 Agent 记录自动同步，也不属于 `.studio.json` 备份 |
| Agent 没有出图或操作文件的能力怎么办？ | 让它说明缺少的能力，先用已有参考或标明的线框讨论。不能读写文件的 Agent 可以讨论方案，实际制作需要能操作本机项目的工具 |

已有明确参考可以缩短探索，小修可直接编辑。以下制作细节供 Agent 查阅，用户无需逐项学习。

## 微调、蓝图与交接怎么选

- 改字号、颜色、间距：拾取后在编辑页调整，或用画布「实际布局」拖动，结果自动保存到工程。
- 先试多个部件的布局：进入画布切到「蓝图」，选择并拖动同类部件，最后保存整张蓝图为一张小票。每项可以有不同的编辑范围，手机 / 电脑预览与修改范围要分别确认。
- 只想描述问题：标点评论，或直接在 Agent 对话说明；蓝图不是必经步骤。

保存小票后，在当前对话告知 Agent 即可继续；首次或换 Agent 才复制交接。未保存的蓝图只留在当前标签内存，刷新前保存小票。Agent 落实并验证、用户验收后再应用 / 导出；仅保存蓝图不会改变主题。手机保留预览 / 编辑切换和轻量画布工具条，详细属性用同一编辑页。

## 给 Agent 的制作流程

### 默认路线

```text
先聊想法 → Agent 认识宿主、按布局意愿大胆给图 → 大方向敲定
    → 提取选图结构、按图制作 → 真实截图对照 → 可试用样板
    → 用户微调 / 标注 / 保存蓝图 ↔ Agent 核对基线、落实并验证
    → 完善、验证与交付（设计记录由 Agent 随过程维护）
```

| 阶段 | 用户和 Agent 一起做什么 | 留下什么，才值得继续 |
| --- | --- | --- |
| 认识宿主 | 核对目标版本和功能关系；区分结构参考、现用主题与风格灵感 | 标明来源的参考、可改与需保留的部分、尚未核验项 |
| 设计简报 | 用户只说主题、设备和布局意愿；Agent 随讨论补充具体建议 | 一句起步需求，逐步积累为设计记录 |
| 视觉探索 | 允许大改时主动重构，比较空间、消息形态和阅读体验不同的方向 | 带编号的候选图、各自优缺点、取舍理由 |
| 方向收敛 | 选一个主方向，提取构图与标志部件，明确保留 / 修改 / 舍弃 | 选中图片版本、结构映射、桌面 / 手机策略、样式与素材清单 |
| 原生样板 | 尽量按图复刻阅读面板、两类消息、头像和输入区，接入真实工作台 | 可微调的样板、参考与实际截图对照、差异原因、恢复版本和检查范围 |
| 微调与迭代 | 用户自己调常见参数，标注复杂意见；Agent 接住最新工程继续改 | 保留用户微调的更新、小票结果与实际效果 |
| 完整交付 | 扩展到细节、抽屉和交互状态，逐项验收 | 主题 JSON、工程备份、源码 / 素材及验证范围 |

这些阶段由 Agent 在同一对话中衔接，不要求用户回到工作台切换按钮或抄写记录。已有清晰且选定的参考图，可以直接解释它如何对应宿主，然后做样板；只修圆角或某个遮挡，不必重新跑整轮图。只补问影响下一步的问题，优先提出有依据的选择，让用户看图表达偏好。

## 1. 先认识酒馆，再发挥想象力

Agent 先读项目 `AGENTS.md` 和[宿主参考](host-reference.md)，按其中的功能地图核对阅读区、消息身份与正文、思考区、输入和菜单。它说明知识来源、版本边界以及如何选择参考，不依赖另装上级主题 skill。需要操作真实宿主时再读[真实酒馆工作流](native-lab.md)，在设计工作台（`connector/responsive.html`，旧 `#tts-lab` 自动转入）确认「当前为虚构测试对话」后读取画面；实际修改前保存恢复点。

**测试对话不等于基础外观。** 它仍可能带着用户的旧美化、背景、原生外观设置和扩展样式；「查看原样」恢复的也是现用主题。从零设计优先使用同版本独立基础环境的参考，改造旧主题则明确保留哪些现有部分。暂时没有可用基础环境时，可以依据已核实结构制作标明用途的示意继续讨论，注明未核验部分，不把现用主题全图默认为原生布局。

**理解宿主不等于沿用当前布局。** 用户允许大改时，主动重新组织阅读区、消息呈现、头像名字关系、输入区和装饰空间，让概念图体现显著变化。截图用来认识真实部件、内容和交互，不能把其坐标、圆头像或矩形消息框当作设计边界。Agent 要区分原生 CSS 能实现的排版与需要 DOM 重构或扩展开发的方案，既给大胆方向，也讲清实现方式。用户要求保留大体布局或只做小修时，遵守相应范围。

### 从零设计，工程从哪里开始？

**新主题：** 设计从空白简报开始。准备落地时，优先使用「作品 → 新建作品 → 从空白开始」，填写名称即可得到独立目录、基础源码与实时同步；也可导入来源明确的基础主题。基础起点不代表目标酒馆的默认截图，Agent 仍应核对目标版本原生字段，按选定构图制作。不要清空已有作品来腾位置。作品切换会保存恢复快照，源码、素材与定稿各自保留，具体见[作品目录](work-folders.md)。

**改造旧主题：** 在「作品 → 新建作品」选择「接入酒馆当前主题」或导入旧主题 JSON，创建独立作品；已经在作品库里的主题直接打开继续改。先列出要保留的布局、素材、字号和行为设置，不把「换一种氛围」理解成重置全部偏好。读取当前主题得到的是改造素材，不是干净的原生参考。

「从零共创」里的起点选项只记录意图，不会替换工程。浏览器起步想法仍属于原工程；Agent 应从本次对话沿用需求，在设计记录中更新新工程标识并告知保存位置，不要求用户再次填表。`npm run lab -- examples/starter.theme.json` 的种子参数只对没有工程的数据目录生效，不能用它清空现有工程。

## 2. 一句话起步，细节边看边定

初次只需三项，不知道怎么选也可以让 Agent 提案：

| 用户说什么 | 例子 |
| --- | --- |
| 想做什么主题 | 「暗黑童话」「星际终端」「想要像一本魔法书」 |
| 主要在哪用 | 电脑、手机，或两边都用 |
| 布局能改多大 | 可以大改、保留大体布局，或看图再定 |

工作台默认收起「已有参考或特别要求？（选填）」。已有主题、参考图片、特别喜欢 / 不喜欢的东西、素材倾向可以补充，留空不影响开始。不要把阅读密度、素材清单或验收标准当作用户必须完成的问卷。

Agent 根据这些信息提出具体方向，解释每个方向的排版、阅读感受与手机取舍。长文习惯、必须保留的设置、外链偏好和验收条件，在出现相关选择时再补充；优先给建议或图，而不是一次抛出一长串问题。用户说「暗黑童话，手机，布局大改」时，就应先给可讨论的设计方向。

[设计记录模板](co-design-brief.template.md) 供 Agent 随讨论整理，不要求用户填写。工作台只保存起步想法；Agent 的最新决定记录在主题源码目录的 `design-brief.md`，没有源码目录时暂存于 `output/co-design/<当前工程ID>/design-brief.md`。保存图片与来源，交付或换对话时提供记录和文件路径。不能写文件时提供可复制版本，不声称已自动保存或同步到工作台。

## 3. 让视觉参考成为讨论依据

### 先做有区别的方向，再看图

Agent 通常提出 2–3 个有实质差异的方向；已有清楚方向时不凑数。允许大改时，先想主题自己的界面语言，再将原生部件放进去：阅读区可以像舞台、书页或终端，消息与肖像的轮廓、位置、比例可以重做，菜单也可以重新组织。解释影响选择的**构图、排版、标志性细节和手机取舍**即可，其他制作细节留在记录中。不能只把同一张聊天面板换成紫色、绿色、蓝色，也不能把默认矩形框留住后靠背景图代表全部创新。

例如，同样是「月夜书房」，可以比较连续书页、批注手稿、轻量通讯笺：它们的消息分隔、头像位置、留白与装饰分布应有实质差别。风格隐喻必须映射到酒馆已有部件，Agent 同时说明可实现部分和需要验证的部分。

| 用什么图 | 回答什么问题 | 输入和约束 |
| --- | --- | --- |
| 氛围 / 材质板 | 用户还不确定喜欢哪种气质 | 少量色彩、纸张 / 金属 / 玻璃等材质与文字层次；明确它尚未证明界面可用 |
| 基于宿主结构的界面参考 | 这个方向如何对应酒馆部件 | 标明来源的结构参考、视口与虚构文本；改造时附需继承的现用主题。实际可用性由样板验证 |
| 选定方向的局部放大与手机图 | 消息细节和装饰在小屏上如何取舍 | 选中图片版本、局部问题、明确的手机重排策略；不是简单缩小整张桌面图 |
| 独立生产素材 | 已决定的装饰如何实际使用 | 无文字 / 假按钮、尺寸与锚点、留白、必要的透明背景，按职责分层 |

第一轮通常只需 2–3 个可比较方向。有图像工具时，按[宿主参考](host-reference.md#把参考传给图像工具)分别提供结构依据、风格灵感和需要继承的旧主题元素；从零时避免将高度风格化的旧主题全图作为主要附件。尚在找气氛时可先做材质板，然后回到宿主构图。工具不能用时，给出可复制的出图提示，并用已有参考图或明确标注的线框继续讨论；没有实际产出的图不能写成「已生成」「已看图验证」。

### 一份可直接改写的出图提示

```text
请为 SillyTavern 原生聊天界面制作视觉探索图。本轮目标：[整体构图探索 / 选定方向的局部问题]。
起步想法：[主题关键词、电脑 / 手机、布局可大改 / 保留 / 待定]。
已知补充：[已有偏好或参考；没有可省略，不要求用户先填完]。
结构依据：[已核对的宿主版本与部件关系；未核验部分]。
结构参考附件：[独立基础环境的虚构截图 / 明确标注的部件示意、文件名、视口]。
风格附件：[已有选中方向或灵感图的文件名 / 版本及用途，没有则省略]。
需要继承的旧主题部分：[本次明确保留的布局 / 素材 / 设置；没有则写“无”]。

以附件认识原生部件与功能，保留阅读面板、两类消息、头像名字、消息操作、
输入框及真实按钮的身份与可操作性。布局允许大改时，大胆提出有显著变化的构图，
重做消息轮廓、头像名字关系、菜单组织与装饰层次；附件不是必须沿用的视觉底稿，
不锁定原图坐标，不只换配色和边框。保留布局时在约定范围内探索。正文使用虚构内容。
输出 [2–3 个不同方向 / 已选方向的一处改进]，用独立编号标记，采用相同
视口和相近的样本文本长度。每个方向须在构图、排版、材质层级或装饰语言上有差异。
正文与输入区优先，重要装饰避开文字和点击区域；同时表现窄屏的取舍。
这是待讨论的概念图，图中文字、图标和控件不作为实际 DOM 或功能验收依据。
```

图像工具生成图片后，Agent 要把图展示出来，逐张解释具体设计决定、原生 CSS 可实现部分和实现疑点，再邀请用户用「保留 / 调整 / 放弃」反馈。用户明确说「A 的书页结构 + B 的克制装饰」时，记录组合规则，先修选中的构图，不再每轮全图随机重抽。

比较时至少看：**是否符合氛围、长文读起来是否舒服、消息层级是否清楚、手机是否留足空间、原生控件是否能实现**。视觉图里的文字和图标可能失真，应回到真实控件核验；单张漂亮图片不能证明菜单、滚动和按钮能用。

## 4. 提取选图结构，作为复刻目标

Agent 从对话中整理并更新设计记录：选中图文件名 / 编号和版本、喜欢的区域、仍需改的区域、明确舍弃项、下一步与验证范围。用户只需自然表达喜好，已有选择与授权沿用，不重复要求确认同一个方向；旧记录与本次对话不一致时，以用户最新决定为准。用户选好并同意制作后，直接衔接样板，不要求回工作台复制第二段提示。

选图后，以**尽量一比一复刻参考图**为制作目标；用户的最新修正优先于图。逐项提取结构与标志细节，并映射到实际原生部件，记录在 `design-brief.md`，由 Agent 整理，不要求用户填写：

| 决定 | 示例内容 |
| --- | --- |
| 整体构图 | 导航 / 抽屉的位置与开关、阅读区和输入区的比例、留白、对齐与重叠 |
| 消息形态 | 两类消息的轮廓、底纸 / 气泡尾、宽度与错位；不是只有颜色和边框 |
| 头像与名字 | 肖像裁切、尺寸、倾斜，位于气泡内 / 外及名字压边关系；保留真实角色头像 |
| 排版 | 正文宽度、字号行高、消息间距、名字 / 时间 / 操作栏关系 |
| 视觉层级 | 背景、阅读面板、消息、抽屉的前后关系、比例与对比 |
| 设计变量 | 文本 / 弱化文本 / 强调色、边框、圆角、阴影与间距；说明各自用途 |
| 素材清单 | 每张图的职责、透明需求、锚点、显示尺寸、手机替代方案 |
| 状态与限制 | 长文、多行输入、思考折叠、hover / focus、菜单展开及需单独验证的扩展 |

标出决定这个方向的结构、首版要实现的区域，以及稍后补充的细节。色板只是其中一项；不能把「按图制作」缩成提取配色，再沿用旧头像、旧消息框和旧排版。复杂装饰先说明布局占用与层级，不能靠把正文缩窄来凑参考图。只有一张效果图时也不要把含假文字和按钮的整图铺成背景。

## 5. 做贴近参考图的原生样板，再对照修正

大方向得到认可且本轮已要求制作，就按选图完成阅读面板、角色消息、我的消息、头像名字和输入区。**先交样板是缩小制作范围，不是降低所选区域的视觉还原目标。** 首版要落实决定该方向的构图、轮廓、比例、叠层与必要装饰；次要纹理和精确参数可以待定，不等所有细节定稿才给用户试。Agent 负责准备工程、接入工作台与真实虚构测试对话，保存「原生样板」版本。

制作顺序跟随选图：先建立整体空间和部件关系，再实现消息 / 头像 / 名字的轮廓与层级，最后补排版、材质和点缀。获准从零或大改的区域采用新的样式结构，处理冲突的旧规则；不能默认在旧美化上调整几项颜色、圆角和边框就交样板。CSS 排版、伪元素、裁切与独立透明素材按需要组合，真实控件仍由宿主负责行为。

### 消息框长文适配

有具象消息框装饰时，在生成生产素材前区分固定角部 / 头尾、可重复边段和阅读内腔；选择九切片、独立分块或适合延展的 CSS 结构。不能把整张椭圆膜囊、花框或气泡按正文高度拉长；九切片也要核对弧线和纹样有没有落入拉伸区。只有允许变形的部分可拉伸，精细纹饰按段重复，内腔纹理单独检查。

复杂异形框可采用固定头尾、重复侧边和独立内腔；若上下沿需要弧形收口，再用固定高度轮廓承载固定尺度的材质。长文只增加中段和边节，改变宽度时也不压扁具象纹样。独立材质的轮廓遮罩与掩盖整框拉伸的补丁应区分，具体像素值和挂载位置留在作品源码说明中。

素材不适合可变高度时，应在已有授权范围内重新分块或重绘，不叠加遮罩来掩盖已变形的头尾。正文按真实内腔留白，避免透明缺口和尖角；不靠截断正文或固定消息高度凑截图。

桌面、手机分别检查两类消息的单行 / 短消息、常见长度和跨多屏长文；长文必须查看顶部、中段、底部。检查固定图案比例、重复接缝、正文边距和相邻消息间隔。没有横向溢出只能证明几何边界，不能替代图案是否失真的视觉检查。

### 分块装饰的自然融合

把自然融合纳入出素材、拼装与验收三个阶段，让最终装饰呈现连续整体。

1. **出素材时设计接口。** 同组图片沿用一致的材质参考、光照、色相、纹理尺度和边缘厚度；明确头侧、尾侧、上下沿及内腔的接触区域、锚点与遮挡关系，预留可衔接的边缘。参考需要立体材质时，上下沿应表现其层叠和高光，不能只用细线代替。
2. **先做局部接缝样板。** 用实际显示尺度检查相邻两块；先连接轮廓和纹理，再用小范围搭接、专门衔接段或局部透明过渡处理接缝。有机主题可让甲片压住筋膜、纤维延续到下一段，使接头有结构依据。避免半透明叠加形成暗带或双重高光；接口不匹配就修对应区域，不靠大面积模糊或压暗遮掩。
3. **整框检查重复与融合。** 固定纹样尺度，检查宽度变化及长文增加边段后是否仍自然。自然材质避免醒目结节、高光在接头机械重复；规则纹样保持原本节奏。桌面、手机分别看整体与放大的接缝，核对硬切线、露底、透明毛边、材质厚度和光照突变，同时保留正文、回复切换和原生操作空间。

在设计记录中写明固定部分、重复部分、接口处理方式及截图证据。比例稳定和拼接自然分别验收；无溢出、边界对齐不能替代视觉检查。这些规则适用于需要分块的装饰，不要求轻量主题额外生成素材。

### 展示前，比较参考与实际效果

收起工作台，以对应视口和相近虚构文本长度保存真实截图，与选定图逐项比较：整体构图、消息轮廓、头像名字关系、空间比例、层级、标志装饰。桌面与手机分别比较，手机按选定策略重排，不能只缩小桌面。

明显偏离的核心结构先修，再检查阅读和原生操作、展示试用入口。「按钮还能点」证明可用性，不能证明已经贴近选图；几何检查无溢出也不能代替视觉比较。

差异按实际原因处理：尚未实现就继续制作；CSS 冲突就查计算样式和层叠；确有宿主约束就记录具体 DOM / 原生行为依据与尝试结果，给出最接近的可用替代。不要未尝试重排就以「酒馆只能换皮」降级；确需新增结构或扩展功能时说明范围，继续完成已授权部分。

本次 P5 共创暴露的差距是：概念图已有斜切肖像与剪纸气泡，首版仍像旧框换色。有效的修正是重做头像裁切、气泡外的位置、名字压边、纸片轮廓与双方消息对齐，然后分别验证桌面和手机。增加背景装饰不能替代这些结构变化。其他主题按自身参考图提取目标，不照搬 P5 形状。

**样板就绪时只需教两件事：**「拾取元素」可自行调字号、间距等；「标点评论」可指出要 Agent 改的位置。不要求用户读 API、配置构建器或学习图层模型。常调参数留下稳定的 CSS 变量或部件覆盖入口，避免普遍使用 `!important` 导致面板调整无效。工作台是实时预览和共同修改的地方，不是必须填完的设计流程表。

向用户展示实际截图，并简短说明已复刻的关键部分和剩余差异，在记录中保留具体原因与下一步。布局尚未成立时先修样板，避免批量制作最后用不上的装饰。预览可呈现聊天布局、头像样式等已支持的外观，但不写入酒馆设置；未覆盖的原生行为及持久效果要在应用后检查。

样板通过后再扩展正文、引用、代码、表格、思考区、菜单和抽屉。复杂主题保留可维护 CSS 和素材来源，通过 [源码同步](source-build.md) 或 CLI 导入到当前工作台；通用新主题要使用自己的源码，不必运行月弧示例构建器。

素材需要时才生成。背景、透明点缀、边框分别准备；核对真实 alpha、不同底色的边缘、裁切、清晰度和体积。已定稿图片原样保存，移动或缩小不等于重新绘制。通过「素材 → 素材库」上传生产资源，按职责接入变量 / 图层；记录来源和可分发范围。

## 6. 接住反馈，再完成交付

用户可以直接在面板微调，一般意见在原对话里说；需要定位时用「标点评论」，例如「右侧纹饰不要挤压三行输入」。已有项目对话里，用户告知「标好了」后，Agent 直接读本轮小票；首次或换 Agent 时再复制交接。工作台不自动启动 Agent，也不承诺无人值守监听。用了小票就按快照核对基线、修改并回写证据，用户检查后验收。详见 [进阶协作](advanced-guide.md#agent)。

**保护用户的微调。** 每轮重新读取最新工程、变量 / 部件覆盖和本轮小票，保存恢复点。复杂源码通过 [源码同步](source-build.md) 合并当前界面修改；不要重导旧工程或使用会清掉变量覆盖的 `base-theme` 来做普通迭代。变量映射冲突时先定位并解释，不猜测覆盖。首次导入样板和继续更新当前样板是不同操作。

交付前共同检查：

- 选定参考与实际截图中的构图、消息形态、头像名字关系、比例和装饰是否对应；明确用户修改、已核实限制和未完成差异。
- 长文、短消息、两类消息、Markdown、图片、思考展开 / 折叠、预置 swipe 与编辑状态。
- 顶部菜单和抽屉、输入区与多行输入、点击范围、键盘焦点；真实生成 / 停止需另备场景，静态样本不能冒充已验证。
- 桌面、窄屏与低高度窗口；读取实际视口，收起工作台看完整阅读区域。手机示意图不能代替实体手机与软键盘测试。
- 装饰不截获点击、不遮正文；原生宽度 / 字号等约定保留的控制仍然有效。
- 使用新名称「应用到酒馆」，或下载主题 JSON 后原生导入并选择，关闭预览检查持久效果；同时保留完整作品目录、简报、选定参考与必要源码 / 素材。

把**概念图、真实截图、自动检查、实际验证的版本与未覆盖项**分别写清。只在模拟示例中看过时，如实保留这个限制。完整交付选项见 [验证与交付](advanced-guide.md#delivery)。
