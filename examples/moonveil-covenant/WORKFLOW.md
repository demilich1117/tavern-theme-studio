# 2.0 的新增制作经验

- 从概念中拆出环境、主龙、侧爪、头像环、九宫格框；不能把整张设计图直接当背景。每个素材单独生成，并确认真透明孔、接触基线和可伸缩部分。
- 装饰跨界面时，必须给滚动容器留固定外部空间；只加padding会随着正文滚走，导致后续消息被龙首覆盖。
- 原生页面宽度由 `--sheldWidth` 控制。固定left/right配上width:auto会让滑块失效。保留原生宽度，用max/min限制工具栏安全边距即可。
- 原生数字滑块需按Enter或失焦确认；程序化填值不等同于用户确认。验证应记录设置值与真实几何尺寸。
- 宿主滑轨具有!important，标题有旧渐变，复选框也有自定义绘制；夜间主题必须检查这些计算样式，不能只改accent-color。
- 头像框中心需要足够大。首版虽然透明，但爪子遮脸；v2才具有约61.6%的完整透明内圆。
- 内嵌素材通过压缩与复用保持CSS低于工作台250KB限制。大块data URL在变量面板显示为只读素材说明，避免让用户编辑不可提交的长base64。
- 默认折叠、横排按钮属于连接器结构约束。本版真实复测为默认收起，展开后按钮宽126/126/74px、单行，关闭行为正常。

下面保留旧版制作记录，涉及羊皮纸、月雾和SVG的说明仅适用于1.x。

# 制作这类主题时实际要处理的事

## 先确定完整视觉语言

只有龙图、冷色和细边框，会很容易落入科幻游戏大厅。最终方向把「银龙王庭」落实到材料和部件：典籍封皮、霜色纸页、印玺、折叠缎带、龙翼纹章、银质雕花。漫画画风属于立绘，不要求所有控件都变成漫画游戏 HUD。

1.0 把近半屏让给完整立绘，实际阅读时聊天区显得局促。1.1 把正文放在约八成宽的月雾玻璃上，巨龙由独占半屏改为透过底层提供氛围；用消息最大宽度约束大屏行长。手机缩短装饰页头，并把印玺移到正文上方，让正文获得整行宽度。布局缩窄时不等比例压缩整张桌面界面。

## 设置面板不能统一套一个窄宽度

用户设置原生包含三列，420px 容器会把每列压成细条。阅读版按内容区分 600px 普通面板和 940px 多列面板；用户设置采用最小 240px 的自适应网格，手机明确单列。长标签允许正常换行，原生按钮的 `min-content` 宽度需要一起核对。不能只检查示例聊天区就宣称设置区适配完成。

工具栏放到左边后，角色管理也要跟随入口从左边打开。仅把图标移动到左侧、却保留角色面板的右侧定位，会造成操作方向断裂。保留原生抽屉的开关与锁定逻辑，主题只调整尺寸和位置。

月雾虚化只施加在聊天底层与抽屉自身，不放在工具栏祖先上；使用高不透明度霜色纸页保持文字对比。禁用透明效果或不支持虚化时提供实底回退。

## 起点隔离比叠加 CSS 更重要

旧主题 CSS 留在页面时，新工程即使从空白开始，也会受到旧选择器和 `!important` 的影响。连接器 0.2.1 在临时预览时暂停宿主的 `#custom-style` 样式表，比较或关闭时恢复原来的启用状态；不改写原 CSS 文本。

气泡模式、文档模式、头像形状、隐藏头像、紧凑输入等还受原生 class 控制。连接器现在临时映射这些外观 class，结束后只恢复自己管理的类，保留其他扩展类；不保存 `power_user` 设置。

## 导出必须核对宿主实际格式

SillyTavern 1.19.0 的主颜色应用函数按 `rgba(...)` 拆分颜色。浏览器接受的 `#hex` 不意味着原生主题导入路径也接受。最终 JSON 使用原生 RGBA 格式，CSS 里仍可使用十六进制颜色与变量。

主题必须显式给出布局相关的原生外观默认值，否则原生导入合并过程可能沿用旧主题的气泡/头像等设置。此工程的所有基础值由构建脚本编写，不读取现有主题。

## 装饰不能接管交互

外框、书页花饰和背景使用 `pointer-events: none`。不把 `clip-path` 或 `overflow: hidden` 加在整个聊天页上，以免裁掉菜单、滑动消息或扩展界面。发送、停止、思考内容的可见性继续由酒馆决定。

工具栏祖先上的 `transform` 或 `backdrop-filter` 会改变内部 `position: fixed` 抽屉的定位参照。新版工具栏用不透明的雕刻材质，不建立这类定位上下文。

SVG 用作 `border-image` 时应给出明确尺寸，并把复杂角饰放在切片内部；不能让半个花纹落进会被拉伸的边段。移动端减小边饰尺寸，正文页继续保留自己的留白。

## 亮纸页要成套修改文本颜色

正文、名字、时间戳、引用、强调、链接、代码与编辑区要一起检查。只把消息背景变亮会留下白色文字，造成低对比。此主题为纸页指定墨色，为我方深色缎带保留浅色字，为思考区域单独使用紫灰底。

首字沉排要约束在第一个段落内，否则第一段过短时，会挤压下一段的首行。最终使用段落的独立块格式化上下文容纳首字浮动。

## 资产与工程一起交付

最终立绘压缩为 WebP，主题中的图像约 140 KiB；含内嵌图像与 SVG 的 CSS 约 220,000 字符，保持在当前工作台 250,000 字符的限制以内。图像不放入可编辑 CSS 变量，避免变量面板出现巨大的 Base64 文本框。

保留 PNG、WebP、SVG、提示词、可读 CSS、主题 JSON 和工程 JSON；导入主题只需要一个 JSON。原始生成图片留在生成目录，项目使用副本。

## 检查分三层

1. 结构：原生 RGBA 格式、工程往返、图片自包含、可编辑变量不损坏图像。
2. 示例：桌面和手机的聊天、长文本、引用代码表格、思考、侧栏与多行输入。
3. 真实宿主：原生抽屉与输入、临时预览、查看原样、关闭清理和旧 CSS 恢复。

布局检查不等于审美评价，也不覆盖每一种第三方消息 iframe 的内部界面。主题 CSS 不能穿透 iframe；需要那类界面一起美化时，应另做对应的 iframe 主题或适配层。


## 连接式生物装饰必须先核对解剖与接触线

2.0把上沿双爪与独立侧爪拼在一起，出现三只前爪与比例不一致。2.0.1改成整只龙的单一透明层，上方一只、侧边一只，通过肩肘连续连接。先在原图上测量顶部和侧边接触线，再用同一宽度变量定位；不能独立缩放身体与附肢。同步核查页面宽度变化、边缘裁切、爪尖与正文的避让。原生用户CSS文本框会把CRLF归一化成LF，持久化校验应统一换行后比较。
