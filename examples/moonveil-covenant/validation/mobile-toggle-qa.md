# 2.0.4 手机布局与输入栏修复验收

日期：2026-09-30。目标为本机SillyTavern 1.19.0 / release / 06bde939f，Chrome实际酒馆页面。

## 问题与修复

- 原生mobile-styles.css在1000px以下将body设为fixed，style.css又为html设置transform。根节点因此变为零高度，主题依赖top/bottom的阅读框高度只剩2px，聊天区只剩27px，输入区提前结束并留下约446px空白。
- html明确设置100dvh高度；保留宿主行为，不修改酒馆核心。实际393×852下，阅读框从y153延伸至840，输入框底边839，距视口底部13px。
- 手机阅读框按用户要求居中撑满：393px视口中宽377px，左右各8px；平板左右各12px。侧爪可以自然裁切，根节点overflow-x:clip禁止横向滚动；装饰本身越出视口不视为正文溢出。
- 主题断点对齐宿主1000px，针对宿主的width/left !important规则覆盖阅读框与抽屉位置。
- 手机图标从28.5px缩到18px；左右按钮组取消宿主wrap和固定窄宽度，左侧两按钮同一行，发送按钮34×34。未设置按钮display，原生发送/停止/脚本按钮的显示状态不变。
- 示例模板加入宿主的html transform、手机fixed body和!important宽度规则，使后续预览能暴露同类冲突。

## 实测

- 实际酒馆依次切换393×852、320×740、852×393、980×900、1000×900、1001×900、1440×960，再回到393×852。
- 所有尺寸根高度等于视口，输入区始终贴底；手机/平板阅读框居中，两个左侧按钮处于同一行。
- 最终393×852聊天区约503px高，320×740约381px高。393px时输入框可用宽253px，320px时180px。
- 当前右侧仅发送按钮显示，隐藏的停止及脚本按钮未被主题强制显示。手机用户设置面板仍可打开、关闭。
- 通过原生“更新主题文件”保存，页面提示Theme saved.；保留用户74%桌面页面宽度。测试结束恢复原1764×1271视口。
- 主题导出回归测试及npm run check通过。最终CSS220228字符，四张内嵌WebP150642 bytes。

证据：native-mobile-before.json、native-mobile-after.json、native-mobile-toggle.json。真实页面截图仅保存在项目output目录，不随主题包分发。浏览器模拟视口不等同于实体手机软键盘测试；第三方悬浮按钮继续由各自插件定位。
